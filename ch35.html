C programming basics

When and how long: 30 minutes, with the C questions in the previous years' sets.

Short notes

  • Pointer. A pointer holds an address: &x is the address of x, *p is the value stored at the address in p, and p->m is short for (*p).m.
  • Arrays. a[i] means *(a + i): start at the first element and move i elements along, not i bytes. Passed to a function, an array turns into a pointer to its first element, so the function also needs the length.
  • Pass by value. C copies every argument, so a function that must change the caller's variable takes its address: scanf("%d", &x), addElement(list, &size, 10).
  • Precedence trap. *p++ is *(p++): it moves the pointer. (*p)++ adds 1 to the value.
  • struct. A struct groups fields of different types into one record, and typedef gives it a short name. Its sizeof can be larger than the sum of the fields because of padding, and sizeof arr / sizeof arr[0] gives the number of elements in an array.
  • malloc and free. malloc(n * sizeof(int)) returns a block from the heap, or NULL if it fails. Every block must be freed exactly once and never used afterwards; a block that is never freed is a leak, the classic cause of software aging.
  • Strings. A string is a char array that ends with the zero byte '\0', so "hello" needs 6 bytes and strlen is O(n). Compare strings with strcmp, not ==, which compares addresses.
  • Stack (last in, first out) with an array. top = -1 when empty; push is arr[++top] = x, pop is x = arr[top--]; full when top == MAX - 1.
  • Queue (first in, first out), circular. rear = (rear + 1) % capacity, and the same for front. front == rear both when empty and when full, so keep a size counter or leave one slot always unused.
  • Linked list. Nodes made with malloc, each pointing to the next and the last to NULL. Insert or delete at a known place is O(1), reaching the i-th node is O(i), and deleting the head changes the head pointer itself.
  • Binary search tree. Smaller keys in the left subtree, larger in the right. Search and insert cost O(height): about log2 n if balanced, n - 1 if the keys arrive sorted. An in-order walk prints the keys sorted.
  • Heap. A complete binary tree with parent >= children, stored in A[1..m] with children 2i, 2i + 1 and parent i / 2. Insert and extract-max are O(log m); building from n items bottom-up is O(n).
  • Hash table. A hash function sends a key to a slot, and collisions are handled by chaining or by probing other slots (open addressing). With the load factor alpha = n/m kept low the average cost is O(1); a probe step must share no factor with m, so step 3 works for m = 10 and step 5 does not.
  • Recursion. A base case plus a call on a smaller input. Every call takes a stack frame, so very deep recursion overflows the stack (about 8 MB by default on this Mac, ulimit -s = 8176 KB), and any recursion can be rewritten as a loop with an explicit stack.
  • Running time. Count how often the innermost line runs: full nested loops give n^2, a loop that doubles or halves gives log2 n, and n/1 + n/2 + ... + n/n gives about n ln n. Bubble and insertion sort are O(n^2) (insertion sort is O(n) on sorted input); merge sort and heapsort are O(n log n).
  • Reading code. Integer division drops the fraction toward zero (7 / 2 = 3, -1 / 5 = 0), and % takes the sign of the left side (-1 % 5 = -1). i++ gives the old value and ++i the new one; && and || stop as soon as the answer is known; a static local keeps its value between calls.
  • Undefined behaviour. Reading past an array, using freed memory, signed overflow and i++ + i++ are undefined: the program may print something plausible, crash, or change with the compiler. The sanitizers (-fsanitize=address, -fsanitize=undefined) make them fail loudly.

Questions

CP1. What is a struct in C, and why use it?

Say it: "A struct groups variables of different types under one name, like a student's id, name and points, so they travel together as one record. That keeps code short and safe: one parameter instead of three, arrays of records, and linked lists and trees built from structs that point to each other."

Worked detail: Two applicants to Hiroshima's School of Informatics and Data Science were asked exactly this out loud (02_questions_others_were_asked.md, B4 and B5). The written versions are the fraction struct in the older set II-Q3 and the Student array in August 2025 II-Q3.

#include <stdio.h>

typedef struct {
    int id;
    char name[20];
    int points;
} Student;

struct Padded  { char a; int b; char c; };
struct Ordered { int b; char a; char c; };

void bump(Student *s)     { s->points += 5; }   /* changes the caller's record */
void bump_copy(Student s) { s.points += 5; }    /* changes only a local copy   */

int main(void) {
    Student s = {101, "Alice", 85};
    bump_copy(s);
    printf("%d %s %d\n", s.id, s.name, s.points);
    bump(&s);
    printf("%d %s %d\n", s.id, s.name, s.points);
    printf("sizeof(Student) = %zu\n", sizeof(Student));
    printf("sizeof(struct Padded) = %zu, sizeof(struct Ordered) = %zu\n",
           sizeof(struct Padded), sizeof(struct Ordered));
    return 0;
}

Output:

101 Alice 85
101 Alice 90
sizeof(Student) = 28
sizeof(struct Padded) = 12, sizeof(struct Ordered) = 8
  • bump_copy gets a copy of the whole record, so its change is lost; bump gets the address and changes the original. Use s.points on a struct and p->points on a pointer to one.
  • Student is 4 + 20 + 4 = 28 bytes, with no padding needed. struct Padded is char (1) + 3 padding + int (4) + char (1) + 3 padding = 12, because the int must start at a multiple of 4 and the whole struct must be a multiple of 4. Putting the int first gives 4 + 1 + 1 + 2 padding = 8.

Follow-ups (each builds on your last answer)

  1. Prof: "You said one parameter instead of three. When you pass a struct to a function, is it copied?"
    You: "Yes, C passes everything by value, so passing a Student copies all 28 bytes and the function only changes its copy. In the example, bump_copy leaves the points at 85. So when a function must change the record, or the struct is big, I pass a pointer and use the arrow."
  2. Prof: "You said 28 bytes. Is the size of a struct always the sum of its fields?"
    You: "No, the compiler adds padding so each field starts at an address that is a multiple of its alignment, usually 4 for an int. Student happens to need none, 4 plus 20 plus 4, but a struct of a char, an int and a char takes 12 bytes, not 6, and putting the int first brings it down to 8."
  3. Prof: "Apart from wasting memory, can that padding cause a real failure?"
    You: "Yes, because the layout is the compiler's choice: if I write a struct to a file or a socket as raw bytes and read it back on another compiler or machine, the fields can come out scrambled. The padding bytes also hold leftover junk, so comparing two equal records byte by byte with memcmp can say they differ. So I write and compare the fields one by one."

CP2. What is the difference between an array and a pointer in C?

Say it: "An array is a block of elements next to each other in memory, and in most expressions its name turns into a pointer to the first element, so a[i] means: start at a, move i elements along, and read there. The difference shows in sizeof: in main it gives the whole array, 20 bytes for five ints, but inside a function the parameter is only a pointer, 8 bytes on a 64-bit machine."

Worked detail: Blanks 5, 7 and 9 of January 2025 II-Q3 ask for this pointer style: arr + i for the address of element i (blank 5, for scanf) and *(arr + j) for its value (blanks 7 and 9).

#include <stdio.h>

void show(int a[], int n) {
    printf("inside show: sizeof(a) = %zu\n", sizeof(a));
    for (int i = 0; i < n; i++) printf("%d ", *(a + i));
    printf("\n");
}

int main(void) {
    int a[5] = {10, 20, 30, 40, 50};
    int *p = a;
    printf("sizeof(a) = %zu, sizeof(p) = %zu\n", sizeof(a), sizeof(p));
    printf("a[2] = %d, *(a + 2) = %d, p[2] = %d\n", a[2], *(a + 2), p[2]);
    p = p + 3;
    printf("*p = %d, p - a = %td\n", *p, p - a);
    show(a, 5);
    return 0;
}

Follow-ups (each builds on your last answer)

  1. Prof: "If the function only gets a pointer, how does it know how long the array is?"
    You: "It can't find out from the pointer, so I pass the length as a separate argument, like printList(list, size) in the August 2024 question. The other way is a marker at the end, which is how C strings work: they end with a zero byte."
  2. Prof: "And if the length you pass is off by one, so the loop reads one element past the end?"
    You: "C doesn't check, so it just reads whatever lies next in memory, and that's undefined behaviour. With a loop that runs to i less than or equal to 5 over five elements, a plain build on a Mac printed 151 instead of 150, with no error at all. So a bug like this passes any test that only checks the program doesn't crash."
  3. Prof: "How would you catch it, then? Does boundary testing help?"
    You: "I'd use both: build with AddressSanitizer, a compiler option in clang and GCC that stops the program at the first out-of-bounds read, and put some inputs exactly at the edges, like sizes 0, 1 and the maximum. Your lab's BCD paper plants off-by-one bugs as one of its five kinds of faults, since boundary faults usually look like that, and moves the test inputs toward the boundaries to catch them."

CP3. Why does a function that changes a count take int *size, and what is wrong with *size++?

Say it: "C passes arguments by value, so a function that receives size gets a copy, and adding 1 to the copy is lost. To change the caller's variable I pass its address, ampersand size, and the function adds 1 through the pointer, with brackets around star size. Without the brackets, star size plus plus moves the pointer instead, because plus plus binds tighter than the star."

Worked detail: This is source code 2 of August 2024 II-Q3, blanks [3], [7] and [9] to [14]; its answer warns that *size++ is wrong.

#include <stdio.h>
#define MAX_SIZE 100

void add_copy(int list[], int size, int value)     { list[size] = value; size++; }
void add_pointer(int list[], int *size, int value) { list[*size] = value; (*size)++; }

int main(void) {
    int list[MAX_SIZE];
    int size = 0;
    add_copy(list, size, 10);
    printf("after add_copy: size = %d\n", size);
    add_pointer(list, &size, 10);
    add_pointer(list, &size, 20);
    printf("after add_pointer twice: size = %d, list = %d %d\n", size, list[0], list[1]);

    int x[2] = {5, 0};
    int *p = x;
    (*p)++;                              /* adds 1 to x[0] */
    printf("(*p)++ : x[0] = %d\n", x[0]);
    int y = *p++;                        /* reads x[0], then moves p to x[1] */
    printf("*p++   : y = %d, x[0] = %d, p now points %td int further\n", y, x[0], p - x);
    return 0;
}

Output:

#include <stdio.h>
#define MAX_SIZE 100

void addElement(int list[], int *size, int value) {
    if (*size < MAX_SIZE) {
        list[*size] = value;
        *size++;                     /* the slip: moves the pointer, not the count */
    }
}

int main(void) {
    int list[MAX_SIZE];
    int size = 0;
    addElement(list, &size, 10);
    addElement(list, &size, 20);
    addElement(list, &size, 30);
    printf("size = %d, list[0] = %d\n", size, list[0]);
    return 0;
}

Follow-ups (each builds on your last answer)

  1. Prof: "If star size plus plus is wrong, why does the compiler accept it?"
    You: "Because it's legal C: it reads the count, throws the value away and moves the local pointer, and all of that is allowed. clang does warn, 'expression result unused', even without extra flags, but a warning doesn't stop the build, so I'd turn warnings into errors with the -Werror flag."
  2. Prof: "Suppose the warning was missed. Would a test catch the slip?"
    You: "Yes, if any test looks at the result. With the slip, size stays 0 and every add overwrites slot 0, so after adding 10, 20 and 30 the count is 0 and only 30 is stored. A test that only checks that the program runs without crashing would still pass."
  3. Prof: "How do you know whether your tests are strong enough to catch slips like that?"
    You: "Mutation testing: I plant small slips like this one in copies of the code, called mutants, and measure the share my tests catch, the kill rate. Your lab's BCD paper did this with five kinds of mutants, such as off-by-one bugs and replaced operators, and counted a mutant as killed if some input took a different execution path from the correct program."

CP4. What do malloc and free do, and what can go wrong with them?

Say it: "malloc asks for a block of memory on the heap while the program runs and returns a pointer to it, or NULL if there isn't enough; free gives the block back. I use it when the size is only known at run time, like N read from input, or when data must outlive the function that made it. The classic mistakes are not checking for NULL, forgetting to free, which is a leak, freeing twice, and using memory after it's freed."

Worked detail: This is blanks 1 to 4 and 10 of January 2025 II-Q3, blanks 1-1 and 1-8 of January 2026 II-Q3, and part (3) of the older set II-Q3.

#include <stdio.h>
#include <stdlib.h>

int *allocate(int n) {
    int *arr = malloc(n * sizeof(int));
    if (arr == NULL) {
        fprintf(stderr, "Memory allocation failed\n");
        exit(1);
    }
    return arr;
}

int main(void) {
    int n = 5;
    int *p = allocate(n);
    for (int i = 0; i < n; i++) p[i] = i * i;
    for (int i = 0; i < n; i++) printf("%d ", p[i]);
    printf("\n");
    free(p);
    p = NULL;     /* a later use now fails loudly instead of reading freed memory */
    return 0;
}

Output:

0 1 4 9 16
  • malloc(n * sizeof(int)): malloc counts bytes, so multiply by the size of one element.
  • Check for NULL before using the block. exit(1) needs <stdlib.h>.
  • free(p) once, then p = NULL, so a use after free becomes a NULL access that crashes at once instead of quietly reading freed memory.

A leak, made on purpose:

#include <stdio.h>
#include <stdlib.h>

/* handles one request and forgets to free its buffer */
void handle_request(void) {
    char *buf = malloc(1024);
    if (buf == NULL) return;
    buf[0] = 'x';
}

int main(void) {
    for (int i = 0; i < 1000; i++) handle_request();
    printf("handled 1000 requests\n");
    return 0;
}

The program itself looks fine:

handled 1000 requests

Follow-ups (each builds on your last answer)

  1. Prof: "You said forgetting free is a leak. What does a leak do to a server that runs for weeks?"
    You: "Each leaked block stays reserved until the process ends, so memory use creeps up with every request. After days the machine starts swapping and slows down, and in the end malloc returns NULL or the system kills the process. So it fails because it has run a long time, not because of one bad input."
  2. Prof: "That is software aging. How does our lab deal with it?"
    You: "A leak is the standard example: Prof. Zheng, Prof. Okamura and Prof. Dohi's 2021 paper on rejuvenation and checkpointing names memory leaks and the build-up of round-off errors as aging-related bugs. The remedy is software rejuvenation, a planned restart that returns the system to a clean state, and the paper finds the restart timing that maximises steady-state availability, the long-run share of time the system is up."
  3. Prof: "Would rejuvenation still help if failures came at a constant rate?"
    You: "No. A constant failure rate means exponential lifetimes, and then a freshly restarted system is just as likely to fail in the next hour as an old one, so each restart only adds downtime. Rejuvenation pays only when the failure rate grows with age, which is exactly what a leak causes."

CP5. How are strings stored in C, and why can't you compare them with ==?

Say it: "A C string is just an array of char that ends with a zero byte, written backslash zero, and no length is stored anywhere. So 'hello' takes 6 bytes, and strlen has to walk to the zero, which is O(n). Two strings are compared with strcmp, because double equals only compares their addresses."

Worked detail: The bracket checker in August 2023 II-Q3 loops with data[i] != '\0', which is this idea.

#include <stdio.h>
#include <string.h>

int main(void) {
    char s[] = "hello";
    char t[] = "hello";
    printf("sizeof(s) = %zu, strlen(s) = %zu\n", sizeof(s), strlen(s));
    printf("same address: %d, strcmp(s, t) == 0: %d\n", (void *)s == (void *)t, strcmp(s, t) == 0);
    s[2] = '\0';
    printf("after s[2] = '\\0': \"%s\", strlen = %zu\n", s, strlen(s));

    char buf[4];
    strncpy(buf, "hello", sizeof(buf));          /* copies h, e, l, l and adds no '\0' */
    printf("after strncpy: buf[3] = '%c', so buf has no terminator\n", buf[3]);
    snprintf(buf, sizeof(buf), "%s", "hello");   /* cuts to 3 chars and always adds '\0' */
    printf("after snprintf: \"%s\"\n", buf);
    return 0;
}

Output:

sizeof(s) = 6, strlen(s) = 5
same address: 0, strcmp(s, t) == 0: 1
after s[2] = '\0': "he", strlen = 2
after strncpy: buf[3] = 'l', so buf has no terminator
after snprintf: "hel"
  • sizeof(s) counts the zero byte (6); strlen(s) does not (5).
  • s and t hold the same letters at different addresses, so comparing them as pointers gives 0 (false) and strcmp gives 0 (equal).
  • Writing '\0' at index 2 ends the string there: "he".
  • strncpy with a source that is too long fills all 4 bytes and adds no terminator. snprintf always ends with '\0' (when the size is at least 1), so it keeps 3 letters.

Follow-ups (each builds on your last answer)

  1. Prof: "You said strlen walks to the zero byte. What if the zero byte is missing?"
    You: "Then it keeps reading past the end of the array into whatever memory follows, until it happens to find a zero or touches memory it may not read and crashes. A common way to get there is strncpy: when the source is too long it fills the buffer and adds no zero byte, as in the buf example."
  2. Prof: "Is that only a crash risk, or worse?"
    You: "It can be a security hole, because reading past a buffer can leak whatever data sits next to it. Heartbleed in OpenSSL in 2014 was a close relative: the code trusted a length sent by the other side without checking it against the real message, and sent back up to 64 kilobytes of server memory per request."
  3. Prof: "How could testing have found Heartbleed before release?"
    You: "The key input is a message whose stated length is bigger than its real length, so the generator has to make inconsistent inputs, not only valid ones. A coverage-guided fuzzer, which keeps mutating the inputs that reach new code, does that, and with AddressSanitizer the over-read is reported the first time it happens, even though the reply looks normal. Google's libFuzzer tutorial uses Heartbleed as exactly this demo."

CP6. How do you build a stack with an array, and how does it check brackets?

Say it: "A stack is last in, first out. With an array I keep an index top that starts at minus 1: push moves top up and stores, pop reads at top and moves it down, and it's full when top is MAX minus 1 and empty when top is minus 1. For brackets I push every opening bracket and pop on every closing one; a wrong kind, a pop on an empty stack, or anything left at the end means unbalanced."

Worked detail: This is August 2023 II-Q3. The listing there ignores a full stack (condition 1) and an empty pop (condition 2). This version handles all four conditions, and returns -1 when the stack is too small to decide.

#include <stdio.h>
#define MAX_DATA 5

typedef struct { char arr[MAX_DATA]; int top; } STACK;

void init(STACK *s) { s->top = -1; }

int push(STACK *s, char c) {
    if (s->top == MAX_DATA - 1) return 0;      /* full */
    s->arr[++s->top] = c;
    return 1;
}

int pop(STACK *s, char *out) {
    if (s->top == -1) return 0;                /* empty */
    *out = s->arr[s->top--];
    return 1;
}

/* 1 = balanced, 0 = not balanced, -1 = stack too small to decide */
int check(const char *text) {
    STACK s;
    char top;
    init(&s);
    for (int i = 0; text[i] != '\0'; i++) {
        char c = text[i];
        if (c == '{' || c == '[') {
            if (!push(&s, c)) return -1;                 /* condition 1: full */
        } else if (c == '}' || c == ']') {
            if (!pop(&s, &top)) return 0;                /* condition 2: empty */
            if ((top == '{') != (c == '}')) return 0;    /* condition 3: wrong kind */
        }
    }
    return s.top == -1;                                  /* condition 4: leftovers */
}

int main(void) {
    const char *texts[] = {"{[a]}", "{[[a]}", "{[a]}[", "][[{[a]}]]}", "{[[{[[a]]}]]}", "{[}]"};
    for (int i = 0; i < 6; i++) printf("%-14s %2d\n", texts[i], check(texts[i]));
    return 0;

CP7. What is a circular queue, and how do you tell a full queue from an empty one?

Say it: "A queue is first in, first out: add at rear, remove at front. In an array both indexes only move forward, so a circular queue wraps them round modulo the capacity, rear becomes rear plus 1 mod capacity, and the slots freed at the start get reused. Because front equals rear both when it's empty and when it's full, it keeps a size counter, or leaves one slot always empty."

Worked detail: This is January 2026 II-Q3 with the blanks filled in (capacity 5), plus one line on % with a negative number.

#include <stdio.h>
#include <stdlib.h>

typedef struct {
    int *data;
    int capacity, front, rear, size;
} Queue;

int init(Queue *q, int cap) {
    q->data = malloc(sizeof(int) * cap);
    if (q->data == NULL) return 0;
    q->capacity = cap;
    q->front = q->rear = q->size = 0;
    return 1;
}

int enqueue(Queue *q, int x) {
    if (q->size == q->capacity) return 0;          /* full */
    q->data[q->rear] = x;
    q->rear = (q->rear + 1) % q->capacity;         /* wrap around */
    q->size++;
    return 1;
}

int dequeue(Queue *q, int *out) {
    if (q->size == 0) return 0;                    /* empty */
    *out = q->data[q->front];
    q->front = (q->front + 1) % q->capacity;
    q->size--;
    return 1;
}

int main(void) {
    Queue q;
    int x;
    if (!init(&q, 5)) return 1;
    printf("Initial: front=%d, rear=%d, size=%d\n", q.front, q.rear, q.size);
    enqueue(&q, 10); enqueue(&q, 20); enqueue(&q, 30);
    dequeue(&q, &x);
    printf("Current: front=%d, rear=%d, size=%d\n", q.front, q.rear, q.size);
    enqueue(&q, 40); enqueue(&q, 50);
    dequeue(&q, &x);
    enqueue(&q, 60); enqueue(&q, 70);
    printf("Final: front=%d, rear=%d, size=%d\n", q.front, q.rear, q.size);
    printf("in C: -1 %% 5 = %d, -1 / 5 = %d, (-1 + 5) %% 5 = %d\n", -1 % 5, -1 / 5, (-1 + 5) % 5);
    free(q.data);
    return 0;
}

#include <stdlib.h>

struct Node { int value; struct Node *next; };

    struct Node *n = malloc(sizeof *n);
    if (n == NULL) exit(1);
    n->value = value;
    n->next = head;          /* the old first node comes after the new one */
    return n;                /* the new node is the new head */
}

void remove_value(struct Node **pp, int value) {
    while (*pp != NULL && (*pp)->value != value) pp = &(*pp)->next;
    if (*pp != NULL) {
        struct Node *dead = *pp;
        *pp = dead->next;    /* the link that pointed at dead now skips it */
        free(dead);
    }
}

    for (; p != NULL; p = p->next) printf("%d ", p->value);
    printf("\n");
}

void free_list(struct Node *p) {
    while (p != NULL) {
        struct Node *next = p->next;   /* save it before free */
        free(p);
        p = next;
    }
}

CP9. How do you turn a recursive tree walk into a loop?

        t->left = t->right = NULL;

        t->left = insert(t->left, key);
    } else {
        t->right = insert(t->right, key);
    }

    return -1;

CP12. What is a heap, and how is it stored in an array?

Say it: "A max-heap is a complete binary tree in which every parent is at least as large as its children, so the largest element is at the root. It's stored in an array with no pointers: the children of position i are 2i and 2i plus 1, and its parent is i over 2, rounded down. Insert adds at the end and swaps upward, and extract-max moves the last element to the root and swaps downward, both O(log m)."

Worked detail: This is January 2026 II-Q2, parts (1), (2) and (4); heapsort is the answer to January 2025 II-Q3(4).

#include <stdio.h>

#define MAXN 100
int A[MAXN + 1];      /* A[1..m]; A[0] is unused */
int m = 0;

void swap(int i, int j) { int t = A[i]; A[i] = A[j]; A[j] = t; }

void insert(int x) {                       /* add at the end, then move up */
    A[++m] = x;
    for (int i = m; i > 1 && A[i / 2] < A[i]; i /= 2) swap(i, i / 2);
}

void sift_down(int i) {                    /* move A[i] down to its place */
    for (;;) {
        int big = i, l = 2 * i, r = 2 * i + 1;
        if (l <= m && A[l] > A[big]) big = l;
        if (r <= m && A[r] > A[big]) big = r;
        if (big == i) return;
        swap(i, big);
        i = big;
    }
}

int extract_max(void) {                    /* take the root, move the last to the root */
    int top = A[1];
    A[1] = A[m--];
    sift_down(1);
    return top;
}

void show(const char *label) {
    printf("%-22s [", label);
    for (int i = 1; i <= m; i++) printf("%d%s", A[i], i < m ? ", " : "");
    printf("]\n");
}

int main(void) {
    int in[] = {5, 10, 2, 9, 6};
    for (int k = 0; k < 5; k++) insert(in[k]);
    show("after inserting 5 items:");
    int top = extract_max();
    printf("extract_max returned %d\n", top);
    show("after extract_max:");

    /* bottom-up build of the same five items */
    m = 5;
    for (int k = 0; k < 5; k++) A[k + 1] = in[k];
    for (int i = m / 2; i >= 1; i--) sift_down(i);
    show("bottom-up build:");
    return 0;
}

  1. Prof: "If each insert is O(log n), is building a heap of n items O(n log n)?"
    You: "Inserting one at a time can cost that, but there's a faster way: put all n items in the array as they are, and sift down from position n over 2 back to position 1. That builds the heap in O(n)."
  2. Prof: "Why O(n), when one sift-down can take log n steps?"
    You: "Because most nodes sit near the bottom, where sift-down is short: half the nodes are leaves and do nothing, a quarter move at most one level, an eighth at most two, and so on. CP13. How does a hash table give O(1) lookup, and what happens on a collision?

int T[M];

int h(int k, int i) { return (k + 3 * i) % M; }

int insert(int k) {                    /* returns the slot, or -1 if no slot is free */
    for (int i = 0; i < M; i++) {
        int j = h(k, i);
        if (T[j] == NIL || T[j] == DELETED || T[j] == k) { T[j] = k; return j; }
    }
    return -1;
}

int search(int k) {                    /* returns the slot, or -1 if absent */
    for (int i = 0; i < M; i++) {
        int j = h(k, i);
        if (T[j] == k) return j;
        if (T[j] == NIL) return -1;    /* an empty slot ends the search */
    }
    return -1;
}

void show(void) {
    for (int j = 0; j < M; j++) {
        if (T[j] == NIL) printf(" NIL");
        else if (T[j] == DELETED) printf(" DEL");
        else printf(" %3d", T[j]);
    }
    printf("\n");
}

int main(void) {
    int keys[] = {16, 12, 22, 18, 45, 44, 28};
    for (int j = 0; j < M; j++) T[j] = NIL;
    for (int i = 0; i < 7; i++) insert(keys[i]);
    show();
    printf("search 22 -> slot %d\n", search(22));

    T[search(12)] = NIL;               /* wrong way to delete 12 */
    printf("after emptying 12's slot: search 22 -> %d\n", search(22));

    T[2] = 12;                         /* put 12 back, then delete it properly */
    T[search(12)] = DELETED;
    printf("after a tombstone for 12: search 22 -> slot %d\n", search(22));
    show();
    return 0;
}

Follow-ups (each builds on your last answer)

  1. Prof: "How do you delete a key with open addressing?"
    You: "Not by emptying the slot, because a search stops at the first empty slot it meets. In my example 22 sits in slot 5 only because 12 had taken slot 2, so if I empty slot 2, a search for 22 stops there and says it's missing. Instead I mark the slot as deleted, a tombstone, which searches step over and inserts can reuse."
  2. Prof: "Tombstones pile up. What then?"
    You: "They count as occupied during a search, so probe sequences grow longer even when the table holds few keys. When keys plus tombstones pass a threshold, say half the table, I rebuild into a fresh table with only the live keys. One rebuild costs O(n), but it comes only after about n operations, so the average cost per operation stays O(1)."
  3. Prof: "You said half the table. How much does the fill level matter?"
    You: "A lot, because with a fixed step the occupied slots join into long runs, which is called primary clustering. Knuth's estimate for an insert is one half times 1 plus 1 over (1 minus alpha) squared, with alpha the share of slots in use: 2.5 probes at half full but 50.5 at 90 percent, against 2 and 10 if every probe were random. So tables are resized long before they're full."

CP15. What is the running time of these loops?

Say it: "I count how many times the innermost line runs as a function of n and keep the fastest-growing term. Two full nested loops give n squared, and starting the inner loop at i gives n times n plus 1 over 2, still order n squared; a loop that doubles i runs about log2 n times; and an inner loop with step i runs about n over i times, which adds up to about n ln n."

Worked detail: Running time is asked in January 2025 II-Q3(3), August 2023 II-Q2(5), August 2025 II-Q3(3) and January 2026 II-Q2(4).

#include <stdio.h>

int main(void) {
    int n = 1000;
    long a = 0, b = 0, c = 0, d = 0;
    for (int i = 0; i < n; i++)                 /* (a) full square */
        for (int j = 0; j < n; j++) a++;
    for (int i = 0; i < n; i++)                 /* (b) inner loop starts at i */
        for (int j = i; j < n; j++) b++;
    for (int i = 1; i < n; i *= 2) c++;         /* (c) i doubles */
    for (int i = 1; i <= n; i++)                /* (d) step i */
        for (int j = 1; j <= n; j += i) d++;
    printf("n = %d: a = %ld, b = %ld, c = %ld, d = %ld\n", n, a, b, c, d);
    return 0;
}

For the follow-ups: with k runs and T inputs, counting the pairs of runs that fail on the same input pair by pair costs k(k - 1)/2 * T; counting the failing runs f on each input costs k * T and gives the same total as sum over inputs of f(f - 1)/2. Python check with k = 10, T = 10,000 and simulated beta-binomial failures (p = 0.1, rho = 0.25): both ways counted 14,712 pairs; the share of pairs that both fail was 0.0327 (theory p^2 + rho p(1 - p) = 0.0325), and (share - p-hat^2) / (p-hat(1 - p-hat)) gave rho-hat = 0.255.

Follow-ups (each builds on your last answer)

  1. Prof: "Why does the step-i loop give n log n?"
    You: "The inner loop runs about n over i times, so the total is n times the harmonic number, 1 plus a half plus a third and so on up to 1 over n. That's about ln n plus 0.577, so for n = 1,000 the total is about 7,500; the exact count, rounding up, is 8,053, far below the million of the full nested loop."
  2. Prof: "Where does a quadratic count like that million show up in your own plan?"
    You: "When I count coincident failures: with k runs and T inputs, checking every pair of runs on every input costs k times k minus 1 over 2, times T. For 10 runs and 10,000 inputs that's 45 pairs times 10,000, so 450,000 checks; fine at this size, but it grows with k squared."
  3. Prof: "Can you avoid looking at pairs at all?"
    You: "Yes. For each input I count the failing runs f, and that input has f times f minus 1 over 2 failing pairs, so one pass of k times T steps gives the same total. Divided by all the pairs and inputs, it estimates the chance that two runs both fail, p squared plus rho times p times 1 minus p, which also gives a quick estimate of rho to start the maximum likelihood fit."

CP16. How would you sort an array of structs with the C library's qsort?

Say it: "qsort from stdlib.h sorts any array if I give it the array, the number of elements, the size of one element and a compare function that returns a negative number, zero or a positive number. The compare function receives two void pointers, which I turn into pointers to my struct and compare the field I want, so one qsort can sort students by points, by name or by id."

Worked detail: August 2025 II-Q3 sorts the same five records with a hand-written insertion sort; here the library does it.

#include <stdio.h>
#include <stdlib.h>

typedef struct { int id; char name[20]; int points; } Student;

int by_points(const void *a, const void *b) {
    const Student *x = a, *y = b;
    return (x->points > y->points) - (x->points < y->points);   /* -1, 0 or 1 */
}

int minus_cmp(const void *a, const void *b) {                    /* the common shortcut */
    return *(const int *)a - *(const int *)b;
}

int safe_cmp(const void *a, const void *b) {
    int x = *(const int *)a, y = *(const int *)b;
    return (x > y) - (x < y);
}

int main(void) {
    Student s[] = {{101, "Alice", 85}, {102, "Bob", 92}, {103, "Carol", 78},
                   {104, "David", 88}, {105, "Eve", 90}};
    int n = sizeof s / sizeof s[0];
    qsort(s, n, sizeof s[0], by_points);
    for (int i = 0; i < n; i++) printf("%d %s %d\n", s[i].id, s[i].name, s[i].points);

    int v[] = {2000000000, -2000000000};
    printf("minus_cmp(2e9, -2e9) = %d, safe_cmp = %d\n",
           minus_cmp(&v[0], &v[1]), safe_cmp(&v[0], &v[1]));
    int w[] = {2000000000, -2000000000, 0};
    qsort(w, 3, sizeof w[0], minus_cmp);
    printf("qsort with minus_cmp: %d %d %d\n", w[0], w[1], w[2]);
    qsort(w, 3, sizeof w[0], safe_cmp);
    printf("qsort with safe_cmp:  %d %d %d\n", w[0], w[1], w[2]);
    return 0;
}

Follow-ups (each builds on your last answer)

  1. Prof: "Many people write return a minus b in the compare function. Is that safe?"
    You: "Not for int. If a is 2 billion and b is minus 2 billion, a minus b is 4 billion, which doesn't fit in an int, so it overflows; on a normal machine it wraps to a negative number and qsort puts them in the wrong order. Writing a greater than b, minus a less than b, gives minus 1, 0 or 1 and can't overflow."
  2. Prof: "Your compare function returns 0 for two students with the same points. Does qsort keep them in their original order?"
    You: "Not guaranteed. The C standard says the order of equal elements is unspecified, so qsort need not be stable. If I need stability, I add the original position as a tie-breaker in the compare function, or use a stable sort like the insertion sort in the August 2025 question."
  3. Prof: "Every change to a compare function, like that tie-breaker, can break it. How would you check one before trusting it?"
    You: "I'd check its properties on many random pairs and triples: swapping the arguments must flip the sign, comparing an item with itself must give 0, and it must be transitive, so if a is below b and b is below c, then a is below c. I'd include the smallest and largest possible ints and values near them, since that's where a minus b breaks; that's boundary value testing again, and one such pair already exposes the bug."
