Chapter 22 of 28

Reliability and probability primer

When and how long: Before Monday: sections 2 to 4. Before the oral exam: all of it.

The Dependable Systems Lab measures software quality with probability models. This page covers the ideas in your proposal and the basics the oral exam may touch. Each part has a small worked example. Practise saying each idea in one or two sentences.

1. Probability basics

  • Probability of an event: a number from 0 to 1.
  • Independent events: P(A and B) = P(A) × P(B). Example: two fair coins both land heads with 0.5 × 0.5 = 0.25.
  • Expected value E[X]: the long-run average. A die: (1+2+3+4+5+6)/6 = 3.5.
  • Variance Var(X) = E[X²] − (E[X])²: how spread out X is.
  • Binomial: the number of successes in k independent tries, each with chance p. P(exactly j) = C(k, j) p^j (1 − p)^(k − j).

Check yourself: 3 independent runs, each fails with p = 0.1. Chance all 3 fail? 0.1³ = 0.001.

2. Why "independent failures" is usually wrong (Eckhardt and Lee)

Let θ(x) be the chance that a randomly built version fails on input x. Inputs differ: some are easy (θ near 0), some are hard (θ high).

  • One version fails with p = E[θ(X)].
  • Two versions both fail with E[θ(X)²] = p² + Var θ(X).

So unless every input is equally hard (Var θ = 0), two versions fail together more often than p², the independent value. That's the Eckhardt and Lee result (1985).

Worked example: half the inputs have θ = 0, half have θ = 0.2. Then p = 0.1. Independent guess for "both fail": 0.1² = 0.01. Real value: E[θ²] = 0.5 × 0 + 0.5 × 0.04 = 0.02. Twice as many joint failures.

3. Majority voting (2 out of 3)

Three versions vote. The vote is wrong if at least 2 of 3 fail.

  • On one input with chance θ: P(vote fails) = 3θ²(1 − θ) + θ³ = 3θ² − 2θ³.
  • Over all inputs: E[3θ² − 2θ³].
  • If failures were independent with p = 0.1: 3(0.01) − 2(0.001) = 0.028. Much better than one version (0.1).
  • With the example above (θ = 0 or 0.2): 0.5 × (3 × 0.04 − 2 × 0.008) = 0.5 × 0.104 = 0.052. Voting still helps, but less than independence promises.

Say it simply: voting helps most when versions make different mistakes. When they make the same mistakes, voting helps less.

4. The beta-binomial model (your RQ1)

  • θ varies from input to input between 0 and 1. A Beta(a, b) distribution is a flexible model for that. Mean = a / (a + b).
  • On one input, the number of failing runs out of k is then beta-binomial.
  • Intraclass correlation ρ = 1 / (a + b + 1). ρ = 0 means runs fail independently. Bigger ρ means they fail together more.
  • Overdispersion: the counts are more spread out than a plain binomial would give. That's the sign of shared failures.
  • Fitting: maximum likelihood (pick a and b that make the observed counts most likely). Uncertainty: bootstrap over runs (resample runs many times, refit, look at the spread).

Worked example: a = 1, b = 9. Mean failure chance = 0.1. ρ = 1/11 ≈ 0.09, so there is some shared failure.

5. NHPP software reliability growth models

When testers find and fix faults over time, the number of failures found by time t is modelled as a non-homogeneous Poisson process (NHPP) with mean value function m(t).

  • Goel-Okumoto: m(t) = ω(1 − e^(−bt)). ω = total expected faults, b = detection rate.
  • Failure intensity λ(t) = m'(t) = ωb e^(−bt): it falls as faults are fixed.
  • Remaining faults at time t: ω − m(t).

Worked example: ω = 100, b = 0.1 per week. After 10 weeks: m(10) = 100(1 − e^(−1)) ≈ 63.2 faults found, about 37 left.

The lab's tool pysrat (Prof. Okamura) fits these models to data. Your proposal's optional field-data part uses an infinite-server queue idea: each merged change adds faults that show up after a delay, m(t) = Σ ω_j G(t − τ_j).

6. Availability and Markov chains (Prof. Zheng's other work)

  • Availability = the fraction of time a system works. With mean time to failure MTTF and mean time to repair MTTR: A = MTTF / (MTTF + MTTR).
  • Markov chain: a system jumps between states (up, degraded, down) with fixed rates; the long-run share of time in each state gives availability.
  • Software rejuvenation: restart a system before it ages into failure (memory leaks, etc.). The question is when to restart to get the best availability. Checkpointing saves state so a failure loses less work.

Worked example: MTTF = 1,000 hours, MTTR = 10 hours. A = 1000 / 1010 ≈ 0.990.

7. Confidence intervals and the bootstrap

  • A 95% confidence interval is a range built so that, over many repeats, 95% of such ranges contain the true value.
  • Bootstrap: resample your data with replacement many times, compute the statistic each time, and take the middle 95% of those values.

8. Agreement between checkers and labels (Cohen's kappa)

κ = (observed agreement − chance agreement) / (1 − chance agreement). κ = 1 is perfect agreement, 0 is chance level. Your plan keeps a checker only if it agrees with your hand labels on at least 90% of 20 or more examples, and reports κ.

15 practice questions (with answers)

  1. Two independent versions each fail with 0.2. Both fail? 0.04.
  2. Same, but half the inputs have θ = 0 and half θ = 0.4. Both fail? E[θ²] = 0.5 × 0.16 = 0.08, double the independent value.
  3. Vote failure on an input with θ = 0.1? 3(0.01) − 2(0.001) = 0.028.
  4. Beta(2, 18): mean and ρ? Mean 0.1, ρ = 1/21 ≈ 0.048.
  5. What does ρ = 0 mean? Runs fail independently.
  6. Goel-Okumoto with ω = 50, b = 0.2: faults found by t = 5? 50(1 − e^(−1)) ≈ 31.6.
  7. Failure intensity at t = 0 for the same model? ωb = 10.
  8. MTTF 500 h, MTTR 5 h: availability? 500/505 ≈ 0.990.
  9. Why can't boundary value inputs estimate a failure probability? Too few and not random: 30 to 50 chosen inputs don't represent the input distribution.
  10. What is overdispersion? More spread in counts than a binomial allows; a sign of correlated failures.
  11. Why bootstrap over runs, not over inputs? The same runs meet every input, so runs are the independent units.
  12. Expected value of a fair die? 3.5.
  13. Binomial: 10 tries, p = 0.5, exactly 5 successes? C(10,5)/1024 = 252/1024 ≈ 0.246.
  14. What does an NHPP model? Failure counts over time with a changing rate.
  15. Cohen's kappa of 0? Agreement no better than chance.
