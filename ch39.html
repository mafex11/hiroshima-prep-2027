Chapter 39 of 61

pysrat, hands on

When and how long: Run it yourself first (5 minutes), then read, 20 minutes.

pysrat is Prof. Hiroyuki Okamura's Python package for software reliability models. It is reference [4] in your research plan (you cite version 0.2.7; the current version is 0.2.8). Prof. Okamura may well ask whether you have used it. This page shows a real run, what the numbers mean, and how to talk about it.

Run it yourself first (5 minutes)

It is already installed on your Mac in its own environment. Open Terminal and run:

cd ~/code/personal/masters-research/2027-refresh/hiroshima-application/pysrat-try
.venv/bin/python try_pysrat.py

Then open the two plots in plots/. Once you have run it yourself, everything below is true for you to say. To install it anywhere else: pip install pysrat.

What pysrat is, in plain words

  • It fits NHPP software reliability growth models to fault data: how many faults were found per day (or the time of each failure).
  • The core idea: the expected number of faults found by time t is Lambda(t) = omega x F(t). omega is the expected total number of faults in the software; F is the distribution of the time it takes to detect one fault.
  • It has 12 models, one for each choice of F: exponential (this is the Goel-Okumoto model), gamma, Pareto, truncated normal, log-normal, truncated logistic, log-logistic, four extreme-value models, and CF1, a canonical phase-type model (a chain of exponential phases that can bend to almost any shape).
  • It fits them by maximum likelihood with the EM algorithm. EM treats the unknown total number of faults as missing data, which makes each step simple. The heavy part is written in C++.
  • The interface works like scikit-learn: model.fit(data), then params_, llf_ (log-likelihood) and aic_.
  • It also has a bootstrap module, and metrics-based models where test metrics (test cases, coverage) explain how likely faults are found each day, with AIC stepwise variable selection.

The run: Musa's SS1A data (ships with pysrat)

What the best model (log-logistic) says:

  • Expected total faults: about 161. Found so far: 112 (the model expects 112.5 by day 151).
  • Expected still hidden: about 49 faults.
  • Expected failures in the next 10 days: Lambda(161) - Lambda(151) = 3.8, so the chance of no failure in the next 10 days is e^-3.8 = 0.022.
  • Parametric bootstrap (200 resamples from the fitted model, refit each): 95% interval for omega 122.5 to 231.0. A few of the refits stopped at EM's iteration limit.

Metrics-based model (the README example, dmetrics1: per day, faults, test cases tc, cumulative test cases ctc, coverage cov, cumulative coverage ccov): logit link with all five metrics, AIC 82.895; stepwise selection keeps day, tc and ctc and drops the two coverage columns, AIC 79.074. These match the numbers in pysrat's README, so the install works correctly.

What to take from it

  1. The S-shaped models win. Faults came slowly at first, then faster, then slower. The exponential model can only slow down, so it fits worst and wildly overestimates the total (309).
  2. The model choice changes the answer a lot. Expected total faults range from 119 to 672 across the 12 models, and from 127 to 199 even among the top five. That is why AIC and bootstrap intervals matter, and why the lab works on model selection and model averaging.
  3. AIC trades fit against size. CF1 has the best log-likelihood but more parameters, so its AIC is worse than log-logistic's.
  4. Uncertainty is large. The bootstrap interval for omega is roughly 120 to 230. A single number would hide that.
  5. Link to your plan. In your field-data part, each merged agent change j adds omega_j expected faults found after a delay with distribution G, so m(t) = sum_j omega_j G(t - tau_j). G would come from pysrat's family of detection-time distributions.

Questions and answers

Q1. Have you used pysrat? "Yes. I installed version 0.2.8 and ran it on the Musa SS1A data that comes with it: 151 days, 112 faults. I fitted all twelve models and compared them by AIC."

Follow-ups (each builds on your last answer)

  1. Prof: "Which model fitted best, and why do you think so?"
    You: "The log-logistic model, AIC about 354.7. The cumulative curve is S-shaped: slow at first, then faster, then slower. The exponential model can't bend like that, so it came near the bottom."
  2. Prof: "How different were the models' predictions?"
    You: "Very different. The expected total number of faults went from about 119 to 672 across the twelve models, and from about 127 to 199 even among the best five. So the model choice matters more than the fit plot suggests."
  3. Prof: "Then how would you report the number of remaining faults?"
    You: "With the best model by AIC plus a bootstrap interval. For log-logistic that's about 49 faults still hidden, and a 95% interval for the total of about 122 to 231. I'd also show the top two or three models side by side."

Q2. What does omega mean in these models? "It's the expected total number of faults in the software, including the ones not found yet. The mean value function Lambda(t) is omega times F(t), so omega minus Lambda(T) is what's still hidden."

Follow-ups (each builds on your last answer)

  1. Prof: "And what is F?"
    You: "F is the distribution of the time it takes to detect one fault. An exponential F gives the Goel-Okumoto model, and something like a log-logistic F gives the S-shaped curve."
  2. Prof: "How does pysrat estimate omega and the parameters of F?"
    You: "By maximum likelihood with the EM algorithm. It treats the unknown total number of faults as missing data, which makes each step simple, and the core runs in C++."
  3. Prof: "Did every fit go smoothly?"
    You: "Mostly. A few bootstrap refits stopped at the iteration limit. And the log extreme-value max model gave an omega of about 672, far above the others, which I wouldn't trust without checking it with other starting values."

Q3. What is the reliability for the next 10 days in that example? "About 0.02. The model expects about 3.8 failures in the next 10 days, and the chance of none is e to the minus 3.8. So testing clearly wasn't finished."

Follow-ups (each builds on your last answer)

  1. Prof: "Why is it e to the minus that number?"
    You: "Because in an NHPP the number of failures in an interval is Poisson with mean Lambda(T plus x) minus Lambda(T). The chance of a Poisson count being zero is e to the minus its mean."
  2. Prof: "How would you use that to decide when to stop testing?"
    You: "Set a target, say a 90% chance of no failure in the next release period, and keep testing until the model says we reach it. Or trade the cost of more testing against the cost of failures after release."
  3. Prof: "Would you trust that decision from one model?"
    You: "Not from one model alone. Since the models disagree so much on the total, I'd check the decision under the top few models and with the bootstrap interval before acting on it."

Q4. Why compare models by AIC and not just by log-likelihood? "Because AIC penalises extra parameters. CF1 with three phases had the best log-likelihood, about minus 173.2, but it has more parameters, so its AIC of 358.3 is worse than log-logistic's 354.7."

Follow-ups (each builds on your last answer)

  1. Prof: "What is CF1?"
    You: "A canonical phase-type distribution. The detection time is a chain of exponential phases, so with enough phases it can approximate almost any shape. That flexibility is why it fits well but costs parameters."
  2. Prof: "When would you prefer CF1 anyway?"
    You: "With a lot of data, when none of the simple models fit the shape. Here a three-parameter model is close enough, so AIC prefers the simpler one."
  3. Prof: "Is AIC the only option?"
    You: "No. pysrat also has a bootstrap-based information criterion, and instead of picking one model you can average several, weighted by how well they fit."

Q5. What did the metrics-based model do? "It uses daily test metrics, like the number of test cases and coverage, as covariates for how likely each remaining fault is found that day, with a logit link. With all five metrics the AIC was 82.9. Stepwise selection kept day, test cases and cumulative test cases, dropped coverage, and brought the AIC down to 79.1."

Follow-ups (each builds on your last answer)

  1. Prof: "Why a logit link?"
    You: "A detection probability has to stay between 0 and 1, and the logit maps any linear predictor into that range. pysrat also has probit and complementary log-log links, and the complementary log-log with an offset gives a Cox proportional hazards model."
  2. Prof: "Coverage was dropped. Does that mean coverage doesn't matter?"
    You: "Not necessarily. Coverage and test-case counts move together, so once the test cases are in, coverage adds too little to pay for its parameters. It's about this data set, not a general law."
  3. Prof: "Could covariates like that help in your own study?"
    You: "Yes. In my field-data part each merged agent change has covariates, like the number of added lines, so its expected faults are omega_j equals L_j times e to the beta-prime z_j."

Q6. How would pysrat fit into your plan? "In the field-data part. Each merged agent change adds some expected faults, found after a delay with distribution G, so m(t) is the sum over changes of omega_j times G of t minus tau_j. I'd take G from pysrat's family of detection-time distributions."

Follow-ups (each builds on your last answer)

  1. Prof: "Why not just fit one NHPP to all the fixes?"
    You: "Because agent code keeps arriving. A finite-fault NHPP assumes one fixed code base whose faults get used up, and here new faults keep coming in with every merge."
  2. Prof: "What does your sum look like as a model?"
    You: "It's an infinite-server queue: each change arrives, its faults wait a random time, then get found. Dohi, Osaki and Trivedi used that view to unify finite and infinite fault NHPP models."
  3. Prof: "Where would the fix data come from?"
    You: "From commit messages in about twenty repositories from the AIDev data set, the way Qiu and colleagues used GitHub issues. That part is only if time permits."
