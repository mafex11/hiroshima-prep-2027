Part 2. Research plan

Slide 8. Voting needs versions that fail differently

  • Zheng, Okamura, Dohi [1] · SFPVV 2025 · Voting made strong models, such as GPT-4o, more reliable, but helped little with weak ones. More diversity did not always mean higher reliability.
  • 429 vs ≈ 115 if independent · Ron et al. 2026 [5] · inputs, out of a million, where 2 or more of 48 agent-written programs failed together · Voting over 3 still cut mean failures from 387 to 131
  • 0.43 · 0.27 if all from one model · Nogueira et al. 2026 [6] · of the gain that independent failures would allow, voting over 3 versions · 224 contest problems, 12 models
  • Dark band: Neither 2026 study used a context file. In a real repository, every run reads the same one.

Slide 9. Two research questions

  • RQ1 · SHARED FAILURES. When several agent runs solve one real task with the same context file, how much more often do they fail on the same inputs than independence predicts? Which change between runs lowers it most: file, agent, model or temperature? Measure: ρ of a beta-binomial model (ρ = 0: independent), and how often a 2-out-of-3 vote fails
  • RQ2 · ONE RULE. Does replacing one real rule with neutral text change the reliability of the code, on the pull request's tests and on generated inputs beyond them? Measure: failure probability on the PR's tests and on 10,000+ generated inputs per entry point
  • A checker confirms that each change to the file changed what the agent did. I report this, but it is not an RQ.

Slide 10. Method: repeated runs on real tasks

  • Real task: Merged PR. Its tests fail before, pass after. 138 public tasks [8], plus newer PRs
  • Context file: Original, or one rule replaced by neutral text. About 5 rules × 2 tasks
  • 10 runs each: Claude Code · Codex, 2 models · My harness: open-weight model, 2 temperatures
  • Admit: A run counts as a version only if it passes the PR's tests
  • Test beyond: 10,000+ random inputs per entry point, compared with the merged code
  • 820 runs: 400 main, 100 second Codex model, 200 harness, 120 screening
  • ≈ 420 to 590 USD: at the per-task costs in [8]
  • BCD [2]: the lab's boundary value method, as a stress test

Slide 11. One number for "fail together"

  • θ(x) = chance that a run fails on input x · p = mean of θ over the inputs
  • Formula box: P(two runs both fail) = p² + Var θ(X)
  • Independent only if Var θ = 0: every input equally hard (Eckhardt and Lee [11])
  • Picture, "Same p = 0.2 in both": "Every input equally hard" (eight bars at 0.2) → both fail: 0.04 · "Half easy, half hard" (four bars at 0, four at 0.4) → both fail: 0.08
  • Band: Beta model for θ: the number of failing runs on one input is beta-binomial. One number, ρ, measures dependence: 0 = independent, 1 = always fail together. It also gives how often a 2-out-of-3 vote fails, and the best number of runs.

  • Year 1 · second half: Main runs. Failures beyond the tests (RQ2)
