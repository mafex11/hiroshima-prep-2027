Chapter 24 of 45

CS fundamentals: quick review

When and how long: Day 11.

An informatics committee may ask any CS graduate a few basics: the complexity of quicksort, what a hash table does, why 0.1 + 0.2 is not 0.3. Your plan is about testing code, so the testing section matters most. Keep the answers short: one sentence, one example, stop.

How the answers were checked. The numbers here (binary search comparisons, the Dijkstra example, the counting answers, the floating point examples, the coin-change and LCS values, the birthday probability) were run in Python 3.14 on 12 Nov 2026. One surprise worth knowing: in recent Python (your 3.14 does it; I believe it started in 3.12), sum([0.1] * 10) == 1.0 is True, because sum() now adds floats with compensated summation. So use 0.1 + 0.2 == 0.3 (False) as your example, not the sum. Nothing in this file is marked [CHECK].

1. Big-O

  • Definition. f(n) = O(g(n)) if there are constants c > 0 and n0 with f(n) <= c g(n) for all n >= n0: an upper bound on growth. Omega is a lower bound, Theta is both.
  • Common classes, slowest growth first: 1, log n, n, n log n, n^2, n^3, 2^n, n!.
  • Recurrences you should know: T(n) = T(n/2) + 1 gives log n (binary search). T(n) = 2T(n/2) + n gives n log n (merge sort). T(n) = 2T(n/2) + 1 gives n (tree traversal).
  • Amortised cost: a dynamic array doubles its size when full, so one append may cost O(n), but the average over many appends is O(1).

2. Sorting

Algorithm Best Average Worst Extra space Stable?
Insertion sort n n^2 n^2 1 yes
Merge sort n log n n log n n log n n yes
Quicksort n log n n log n n^2 log n (stack) no
Heapsort n log n n log n n log n 1 no
Counting / radix n + k n + k n + k n + k yes
  • Quicksort's worst case comes from bad pivots, for example always picking the first element of an already sorted array. A random pivot makes it very unlikely.
  • Stable means equal keys keep their original order.
  • Lower bound: any comparison sort needs about log2(n!) comparisons, which is about n log2 n, because a decision tree with n! leaves has height at least log2(n!). (log2(10!) = 21.8.)
  • Python's sorted uses Timsort: stable, n log n worst case, close to n on nearly sorted data.

3. Binary search

  • On a sorted array, compare with the middle and keep the half that can contain the target. O(log n).
  • At most ceil(log2(n + 1)) comparisons: 20 for 1 million items, 30 for 1 billion.
  • Typical bugs: off-by-one in the bounds (a boundary value bug), an infinite loop when lo and hi stop moving, and overflow of (lo + hi)/2 in fixed-width integer languages (write lo + (hi - lo)/2).

4. Hashing

  • A hash function maps a key to a bucket. A hash table gives average O(1) insert and lookup, worst O(n) if many keys collide.
  • Collisions are handled by chaining (a list per bucket) or open addressing (probe the next slots). Keep the load factor (items per bucket) bounded by resizing.
  • Collisions come sooner than you think: with 365 buckets, 23 keys already collide with probability 0.507 (the birthday problem).
  • Python's dict and set are hash tables.

5. Trees and heaps

  • Binary search tree: left subtree < node < right subtree. Search and insert cost O(height): O(log n) if balanced (AVL, red-black), O(n) if you insert sorted keys into a plain BST. In-order traversal gives the keys in sorted order.
  • Binary heap: a complete binary tree where each parent <= its children (min-heap). find-min O(1), insert and extract-min O(log n), build from n items O(n). It is the usual priority queue (Python heapq).

6. Graphs

  • Storage: adjacency list, O(V + E) space (good for sparse graphs). Adjacency matrix, O(V^2).
  • BFS: a queue, level by level. Shortest paths by number of edges in an unweighted graph. O(V + E).
  • DFS: a stack or recursion, as deep as possible first. Cycle detection, topological sort, connected components. O(V + E).
  • Dijkstra: shortest paths from one source with non-negative weights. Repeatedly take the closest unfinished vertex from a priority queue and relax its edges. O((V + E) log V) with a binary heap. It fails with negative edges, because a finished vertex could later get a shorter path. Use Bellman-Ford (O(VE)) then. All pairs: Floyd-Warshall, O(V^3).
  • Worked Dijkstra example. Edges A-B 4, A-C 1, C-B 2, B-D 1, C-D 5 (undirected). From A: take A (0); relax C = 1, B = 4. Take C (1): B = min(4, 1 + 2) = 3, D = 6. Take B (3): D = min(6, 3 + 1) = 4. Take D. Distances A 0, C 1, B 3, D 4; path A-C-B-D.
  • Topological sort orders a DAG so every edge goes forward, for example a build or dependency order.
  • Minimum spanning tree: Kruskal (sort edges, add if no cycle, union-find) or Prim (grow from a vertex).

7. Dynamic programming

  • Use it when a problem has optimal substructure (the best answer is built from best answers to subproblems) and overlapping subproblems (the same subproblem appears many times). Store each subproblem's answer once.
  • Top-down with memoisation, or bottom-up with a table.
  • Examples: Fibonacci in O(n) instead of exponential. Longest common subsequence in O(mn) (LCS of ABCBDAB and BDCABA has length 4). Edit distance O(mn). 0/1 knapsack O(nW), which is "pseudo-polynomial" because W is a number, not an input size. Ways to make 10 from coins 1, 2, 5: 10.

8. P, NP and what is hard

  • P: problems solvable in polynomial time.
  • NP: problems whose yes-answers can be checked in polynomial time, given a certificate (for example a satisfying assignment).
  • NP-complete: in NP, and every NP problem reduces to it in polynomial time. SAT (Cook-Levin), 3-SAT, vertex cover, subset sum, the decision version of TSP.
  • NP-hard: at least as hard as NP-complete problems, but not necessarily in NP (for example the optimisation version of TSP).
  • P is inside NP. Whether P = NP is open. Most people believe P != NP.
  • Undecidable is a different, stronger thing: no algorithm at all. The halting problem is undecidable. A consequence for testing: no tool can decide every program's correctness in general, which is why testing samples inputs.
  • Plain words: "P is what we can solve fast. NP is what we can check fast. Nobody has proved they are different, but nobody has found fast algorithms for the hardest NP problems either."

9. Logic, sets and counting

  • Logic: p -> q is the same as (not p) or q, and as its contrapositive (not q) -> (not p). Not its converse. De Morgan: not(p and q) = (not p) or (not q).
  • Sets: |A or B| = |A| + |B| - |A and B|. A set of n items has 2^n subsets.
  • Functions: injective (one-to-one), surjective (onto), bijective (both, so invertible).
  • Equivalence relation: reflexive, symmetric, transitive. It splits a set into classes, which is the idea behind equivalence partitioning in testing.
  • Counting: n! orderings. n!/(n - k)! ordered choices. C(n, k) = n!/(k!(n - k)!) unordered choices (C(5, 2) = 10). A complete graph on 10 vertices has C(10, 2) = 45 edges.
  • Pigeonhole: n + 1 items in n boxes means some box has two.
  • Induction: prove the base case, then "true for n implies true for n + 1".

10. Floating point pitfalls

  • IEEE 754 double: 1 sign bit, 11 exponent bits, 52 fraction bits (53 significant bits), about 15 to 17 decimal digits. Machine epsilon 2^(-52), about 2.2e-16.
  • 0.1 has no exact binary form, so 0.1 + 0.2 == 0.3 is False in Python (the sum is 0.30000000000000004).
  • Compare with a tolerance, for example math.isclose(a, b, rel_tol=1e-9). Your plan's "float tolerance" rule for comparing outputs exists for this reason.
  • Absorption and cancellation: (1e16 + 1) - 1e16 gives 0.0, because 1 is below the precision at 1e16. Subtracting nearly equal numbers loses relative accuracy.
  • Integers above 2^53 are not all representable: float(2**53 + 1) == float(2**53) is True.
  • NaN != NaN. There is a -0.0. Overflow gives inf. The order of a sum can change the result.

11. Software testing (the part closest to your plan)

  • Levels. Unit test: one function or class alone, often with fakes for its dependencies. Integration test: several parts together (database, API). System and acceptance tests: the whole product against the requirements. Regression tests: re-run old tests after a change.
  • Black-box design.
    • Equivalence partitioning: split inputs into classes the program should treat alike, and test one value per class.
    • Boundary value analysis: bugs cluster at the edges, so test on and next to each boundary. For a valid range 1 to 100: 0, 1, 2, 99, 100, 101.
  • White-box coverage. Statement coverage: every line runs. Branch coverage: every decision goes both ways. MC/DC: each condition independently changes the decision (used in avionics). 100% coverage does not mean no bugs: it says the code ran, not that its output was checked.
  • Mutation testing. Make small changes (mutants) to the code, such as > to >= (relational operator replacement, ROR), + to - (AOR). A test suite kills a mutant if some test fails on it. Mutation score = killed / (total - equivalent). Equivalent mutants behave like the original and cannot be killed. Example: 50 mutants, 5 equivalent, 36 killed gives 36/45 = 0.8. The mutant x > 0 to x >= 0 is killed only by a test with x = 0: boundary values kill ROR mutants, which is the link to the lab's boundary paper [2].
  • Test oracle problem: knowing the right output for a generated input is hard. Options: a reference implementation, properties (for example "sorting keeps the length and gives non-decreasing order"), or metamorphic relations.
  • Differential testing: run two implementations on the same inputs and flag disagreements. Your plan uses the merged code as the reference. Its limit: a bug that both share is invisible.
  • Property-based testing: generate many inputs from types and check properties (Hypothesis in Python). Your input generator built from type hints is in this family.
  • Flaky tests pass or fail without a code change (timing, order, network). Re-run and drop them, as your plan does.

20 short Q&As (spoken answers)

1. What does O(n log n) mean?

"That the running time grows at most like n log n, up to a constant, for large n. Merge sort is an example."

2. Quicksort or merge sort?

"Quicksort is usually faster in practice and sorts in place, but its worst case is n squared and it isn't stable. Merge sort is always n log n and stable, but needs extra memory."

3. Why can't a comparison sort beat n log n?

"Each comparison has two outcomes, and the algorithm must tell apart n factorial orderings, so it needs at least log2 of n factorial comparisons, which is about n log n."

4. How many comparisons does binary search need for a million items?

"At most about 20, because 2 to the 20 is just over a million. It's O(log n), but only on sorted data."

5. Why is a hash table O(1), and when isn't it?

"A good hash spreads keys evenly, so each bucket holds a few items on average. If many keys collide, a lookup degrades to O(n), so the table resizes to keep the load factor low."

6. BST or heap?

"A balanced BST keeps everything in order, so it supports search, min, max and range queries in log n. A heap only keeps the minimum on top, which is all a priority queue needs, and it's simpler and faster for that."

7. BFS or DFS?

"BFS finds shortest paths by number of edges, because it explores level by level. DFS goes deep first and is natural for cycle detection and topological sorting. Both are O(V + E)."

8. How does Dijkstra work, and when does it fail?

"It repeatedly takes the closest unfinished vertex and relaxes its edges, using a priority queue. It assumes non-negative weights; with a negative edge a finished vertex could still get shorter, so I'd use Bellman-Ford."

9. What is dynamic programming?

"Solving a problem by combining answers to overlapping subproblems and storing each answer once. Fibonacci goes from exponential to linear time that way."

10. Explain P versus NP.

"P is the set of problems we can solve in polynomial time, NP the set whose answers we can check in polynomial time. Every P problem is in NP; whether they are equal is the biggest open question in computer science."

11. Is the halting problem NP-complete?

"No, it's undecidable: no algorithm solves it at all, however slow. NP-complete problems can be solved, just not known to be solvable fast."

12. Why is 0.1 + 0.2 not equal to 0.3 in Python?

"Because 0.1 and 0.2 have no exact binary representation, so the sum is 0.30000000000000004. I compare floats with a tolerance, like math.isclose."

13. How do you compare float outputs in your differential tests?

"With a fixed relative and absolute tolerance, written down in advance. Otherwise harmless rounding differences would count as failures."

14. Unit test or integration test?

"A unit test checks one function alone and is fast and precise. An integration test checks that parts work together, so it catches interface bugs that unit tests miss."

15. Does 100% branch coverage mean the code is correct?

"No. It means every branch ran, not that the outputs were checked, and it says nothing about inputs that take a covered branch with a wrong value. That's why I also use mutation testing and generated inputs."

16. What is mutation testing?

"I make small changes to the code, like turning greater-than into greater-or-equal, and see whether the tests catch them. The mutation score is killed mutants over non-equivalent mutants, and it measures how strong the tests are."

17. Boundary values for a function that accepts ages 18 to 65?

"Three classes: below 18, 18 to 65, above 65. Boundary values 17, 18, 19 and 64, 65, 66, plus maybe a non-integer or a negative value."

18. What is the test oracle problem, and how does your plan handle it?

"For a generated input, I need to know the right output. I use the merged code from the pull request as the reference, and I check 20 disagreements per task by hand to drop inputs where the merged code itself is wrong."

19. What is the main limit of differential testing?

"It can't see a bug that both implementations share. In my plan that's exactly the shared-helper case, so I state it as a limit."

20. How many numbers from 1 to 100 are divisible by 2 or 3?

"By inclusion-exclusion: 50 divisible by 2, plus 33 by 3, minus 16 by 6, so 67."
