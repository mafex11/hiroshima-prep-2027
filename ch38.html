Machine learning basics

When and how long: 30 minutes.

Part II Question 6 of every program set is machine learning: the softmax in August 2023 II-Q6, overfitting and supervised against unsupervised learning in January 2024 II-Q6, K-fold cross-validation and activation functions in August 2024 II-Q6, the gradient of logistic regression in January 2025 II-Q6, the confusion matrix, precision, recall and F-score in August 2025 II-Q6, and the Bayes decision rule with a loss in January 2026 II-Q6; least squares is Part II Question 5 in August 2023 and January 2024. Out loud, applicants to Hiroshima's School of Informatics were asked "What is the difference between machine learning and statistical analysis?" (02_questions_others_were_asked.md, B2 and B3), and this file is the short spoken version of all of it, tied to the lab's own machine learning papers where it can be.

How this was checked. Paper facts were checked against the PDF text in 07_Lab_Papers or the abstracts in the extracted text folder, and facts about you against your plan, CV and the Yuki fact sheet. Short notes

  • Supervised learning. Every training example has an input x and the right answer t, a label, and the model learns the map x -> t: classification when t is a class, regression when t is a number.
  • Unsupervised learning. There are no labels, so the algorithm finds structure in x alone: clusters (k-means), a few main directions (PCA), or the shape of the distribution.
  • Machine learning against statistical analysis. Statistics mainly wants to explain: it assumes a probability model and gives estimates, intervals and tests. Machine learning mainly wants to predict, and judges a model by its error on data it has not seen.
  • Linear regression. y = Xw + noise. Least squares minimises ||y - Xw||^2, which gives the normal equations X^T X w = X^T y, so w = (X^T X)^(-1) X^T y; with normal noise this is also the MLE.
  • Logistic regression. P(t = 1 | x) = sigma(w^T x + b), so the log-odds log(p/(1 - p)) = w^T x + b is linear. e^(w_j) is the odds ratio for one unit of x_j, the boundary w^T x + b = 0 is a hyperplane, and the fit is by maximum likelihood with no closed form.
  • Sigmoid. sigma(a) = 1/(1 + e^(-a)), sigma'(a) = sigma(a)(1 - sigma(a)), at most 1/4 (at a = 0), and sigma(-a) = 1 - sigma(a).
  • Softmax. p_j = e^(z_j) / sum_k e^(z_k). Adding a constant to every z_j changes nothing, dp_j/dz_i = p_j(delta_ij - p_i), and with two classes it is sigma(z_1 - z_2).
  • Loss functions. Squared error (1/2)(y - t)^2 for regression; cross-entropy -[t ln y + (1 - t) ln(1 - y)] for classification, which is the negative log-likelihood. With sigmoid or softmax plus cross-entropy, the gradient is sum_n (y_n - t_n) x_n.
  • Gradient descent. w <- w - eta grad E(w). Too small an eta is slow, too large overshoots; on a quadratic it is stable only for eta < 2 / (largest eigenvalue of the Hessian). Stochastic gradient descent uses a small random batch per step.
  • Overfitting. Low training error, high error on new data: the model learned the noise. Expected squared error = noise + bias^2 + variance; a simple model has high bias, a flexible one high variance.
  • Regularisation. Add a penalty for large weights. Ridge (L2): w = (X^T X + lambda I)^(-1) X^T y, shrinks every weight. Lasso (L1): sets some weights exactly to 0. Elastic net uses both. Early stopping and dropout also regularise.
  • Cross-validation. K-fold: train on K - 1 folds, check on the one left out, K times, average. K = 5 or 10; K = n is leave-one-out. For time-ordered data, train on the past and check on the future.
  • Confusion matrix. TP, FP, FN, TN. Accuracy = (TP + TN)/N, precision = TP/(TP + FP), recall = TP/(TP + FN), specificity = TN/(TN + FP), false positive rate = 1 - specificity.
  • F1. The harmonic mean of precision and recall: 2PR/(P + R) = 2TP/(2TP + FP + FN). It is pulled down by the smaller of the two.
  • ROC and AUC. The ROC curve plots recall (true positive rate) against the false positive rate as the threshold moves. AUC = P(a random positive is ranked above a random negative): 0.5 is guessing, 1 is perfect. With rare positives, also look at the precision-recall curve.
  • Bayes decision rule. Conditional risk R(a_i | x) = sum_j lambda(a_i | w_j) P(w_j | x); take the action with the smallest. With 0-1 loss it picks the largest posterior, and its error, the Bayes error, is the lowest any classifier can reach.
  • k-means. Pick k centres, then repeat: assign each point to the nearest centre, move each centre to the mean of its points. It never raises sum_i ||x_i - c(i)||^2 and stops at a local minimum, so run several starts (or k-means++).
  • Decision trees. Split greedily on the feature and cut-off that most reduce impurity: entropy H = -sum p log2 p or Gini 1 - sum p^2. Prune or limit depth. A random forest averages many trees grown on bootstrap samples with random feature subsets.

Questions

ML1. What is the difference between supervised and unsupervised learning?

Say it: "In supervised learning every training example comes with the right answer, a label, and the model learns to map inputs to labels, for example predicting from code metrics whether a module has a bug. In unsupervised learning there are no labels, so the algorithm looks for structure in the inputs, such as clusters in k-means. Supervised results can be checked against known answers; unsupervised results are harder to judge."

Worked detail: This is January 2024 II-Q6(2), which also asks you to explain one algorithm of each kind in about 100 words; the model answers there use logistic regression (ML4 here) and k-means (ML15 here).

Supervised Unsupervised
Data pairs (x_i, t_i) x_i only
Goal predict t for a new x find groups, main directions or the density
Typical tasks classification (t is a class), regression (t is a number) clustering, dimension reduction (PCA), anomaly detection
Examples linear and logistic regression, decision trees, neural networks k-means, PCA, Gaussian mixtures
How it is judged error on held-out labelled data no single right answer: within-cluster distance, silhouette, or how useful the result is later

In between: semi-supervised learning (a few labels, many unlabelled points), self-supervised learning (the labels come from the data itself; a language model learns to predict the next token of text, which is how the models behind coding agents are pretrained), and reinforcement learning (no labels, only a reward after actions).

Follow-ups (each builds on your last answer)

  1. Prof: "You gave bug prediction as a supervised example. Where do the labels come from, and can you trust them?"
    You: "Usually from the bug tracker and the version history: a module is labelled buggy if a later bug-fixing commit changed it, and the SZZ method goes one step further and traces each fix back to the change that introduced the bug. Those labels are noisy, because some bugs are found only much later and some fix commits never say 'fix', so some buggy modules end up labelled clean."
  2. Prof: "If some buggy modules are labelled clean, what does that do to the precision you measure?"
    You: "It lowers it. When the model correctly flags such a module, the label says clean, so it's counted as a false positive, and the measured precision is below the true one. In training, the same wrong labels teach the model that some bug-like modules are safe, so its predicted probabilities come out too low."
  3. Prof: "Your plan has the same problem: a run can pass the tests and still be wrong. How do you deal with labels you can't trust?"
    You: "That's why RQ2 doesn't stop at the pull request's tests: each run that passes them is compared with the merged code on at least 10,000 generated inputs, and I check 20 disagreements per task by hand. The limit I can't remove is a bug that the merged code shares, because then both agree, and I state that in the plan."

ML2. What is the difference between machine learning and statistical analysis?

Say it: "Both fit models to data, but they ask different questions. Statistical analysis mainly wants to understand: it assumes a probability model and draws conclusions with a stated uncertainty, such as a confidence interval. Machine learning mainly wants to predict well on new data, and judges a model by its error on held-out data, even if the model can't be interpreted."

Worked detail: Applicants to Hiroshima's School of Informatics were asked this out loud in two separate 2021 reports, and most felt unsure about it (02_questions_others_were_asked.md, B2 and B3). The real follow-ups in B2 were "What do you mean by statistical knowledge?", "You said intervals, what else?" (they wanted estimation and testing) and "What about many dimensions?", then "How is machine learning used in real life?" and "Name one way to implement machine learning and explain it." The first two follow-ups below copy the second and third of these.

Statistical analysis Machine learning
Main goal explain: which factors matter, how much, how sure predict new cases well
Output estimates with uncertainty: intervals, tests, p values a predictor (a function x -> t)
How it is judged model assumptions checked, inference valid if the model is roughly right error on data the model did not see (held-out data, cross-validation)
Typical models few parameters, interpretable can be very large (forests, neural networks)
Typical data smaller, often designed larger, often just collected

They overlap: logistic regression belongs to both, and machine learning uses maximum likelihood and Bayes all the time. Breiman's paper "Statistical Modeling: The Two Cultures" (Statistical Science 16(3), 2001) calls them the data-modelling culture and the algorithmic-modelling culture, and estimated that about 98% of statisticians then worked in the first. Real-life uses, if asked: spam filters, speech recognition, recommendations, the language models inside coding agents, and in the lab, finding bug-prone modules (Dohi, Wu and Okamura, SOFTENG 2024) and classifying malware from API calls (Li and Zheng, 2021).

Follow-ups (each builds on your last answer)

  1. Prof: "You said statistics gives a stated uncertainty, such as an interval. Besides intervals, what else does statistical inference give you?"
    You: "Point estimates, for example by maximum likelihood, and hypothesis tests, which tell me how surprising the data would be if a claim were true, through a p value. So the three main tools are point estimation, interval estimation and testing, and all three rest on the assumed model being roughly right."
  2. Prof: "What happens to those tools in many dimensions, say more features than data points?"
    You: "Ordinary least squares breaks down: with more features than data points, X transpose X has no inverse, so infinitely many weight vectors fit the data perfectly. I'd add a penalty such as ridge or lasso, or first reduce the dimension with PCA, principal component analysis, which keeps the few directions with the most variance. Testing many features at once also needs a correction for multiple comparisons, like Bonferroni or Benjamini-Hochberg."
  3. Prof: "Penalties are a machine learning habit. Where does our lab mix statistics and machine learning?"
    You: "Wu, Dohi and Okamura's bagging paper at PRDC 2024 starts from a statistical point: the reliability model with the smallest AIC fits past faults best but isn't always the best predictor of future ones. So they use bagging, a machine learning idea, to rank and average models over resampled data, and the abstract reports better predictions in the early and middle phases of testing. The 2024 bug-prediction paper by Dohi, Wu and Okamura goes the other way: an explainable logistic model in place of a black-box classifier."

ML3. How do you fit a linear regression, and what is the least-squares solution?

Say it: "Linear regression models the output as a weighted sum of the inputs plus noise, y = X beta plus epsilon. Least squares picks beta to minimise the sum of squared residuals; setting the gradient to zero gives the normal equations, X transpose X beta = X transpose y, so beta-hat is (X transpose X) inverse times X transpose y when that inverse exists."

Worked detail: Least squares in matrix form is August 2023 II-Q5 (mean and covariance of the fitted values through the hat matrix) and January 2024 II-Q5 (a two-group z test written as a regression); see also 03_statistics.md S20.

minimise S(beta) = (y - X beta)^T (y - X beta)
grad S = -2 X^T (y - X beta) = 0   =>   X^T X beta = X^T y
Hessian = 2 X^T X (positive semidefinite), so this is a minimum; unique if rank X = p.

Example: x = (1, 2, 3, 4), y = (2, 3, 5, 6), with a column of 1s for the intercept
X^T X = [[4, 10], [10, 30]],  det = 20,  inverse = [[1.5, -0.5], [-0.5, 0.2]]
X^T y = (16, 47)
beta-hat = (1.5*16 - 0.5*47, -0.5*16 + 0.2*47) = (0.5, 1.4)
   (same as slope = Sxy/Sxx = 7/5 = 1.4, intercept = 4 - 1.4*2.5 = 0.5)
fitted 1.9, 3.3, 4.7, 6.1; residuals 0.1, -0.3, 0.3, -0.1 (sum 0, and orthogonal to x)
SSE = 0.2, SST = 10, R^2 = 1 - 0.2/10 = 0.98

Follow-ups (each builds on your last answer)

  1. Prof: "Why squared errors and not absolute errors?"
    You: "Squared error is smooth, so calculus gives a closed form, and if the noise is normal with constant variance, least squares is exactly maximum likelihood. Absolute error is more robust to outliers, because a point twice as far off counts twice, not four times, and it estimates the median instead of the mean, but it has no closed form."
  2. Prof: "You said 'if the noise is normal'. Show me that least squares is then maximum likelihood."
    You: "If each y_i is normal with mean x_i transpose beta and variance sigma squared, the log-likelihood is minus n over 2 times the log of 2 pi sigma squared, minus the sum of squared residuals over 2 sigma squared. For any fixed sigma, only the second term depends on beta, and it comes with a minus sign. So maximising the likelihood over beta is the same as minimising the sum of squares."
  3. Prof: "Fault counts per module aren't normal. What would you use for them?"
    You: "Poisson regression: the count is Poisson with mean e to the beta transpose x, so the mean is always positive, and it's fitted by maximum likelihood with no closed form. As I understand from its abstract, the lab's APARM 2024 paper on metrics-based reliability models with elastic net combines this Poisson regression on software metrics with NHPP growth models and fits it with the EM algorithm. My field model's omega_j, L_j times e to the beta prime z_j, has the same exponential-of-a-linear-term shape."

ML4. What is logistic regression, and why not use linear regression for a yes/no outcome?

Say it: "Logistic regression models the probability of class 1 as the sigmoid of a weighted sum, p = 1 over (1 plus e to the minus (w transpose x plus b)), so the log-odds, log of p over 1 minus p, is linear in x. A straight line could predict below 0 or above 1, and a 0/1 outcome doesn't have normal noise with constant variance, so we fit logistic regression by maximum likelihood instead, which has no closed form."

Worked detail: Logistic regression is January 2025 II-Q6 (the gradient), and the model answer chosen for August 2025 II-Q6(3) and January 2024 II-Q6(2); see also 03_statistics.md S21.

Say a fitted model for bug-proneness is logit p = -3 + 0.8 x  (x = a complexity measure)
x = 2: a = -1.4, p = 1/(1 + e^1.4) = 0.198   (odds 0.247)
x = 5: a =  1.0, p = 1/(1 + e^-1)  = 0.731   (odds 2.718)
odds ratio per unit of x = e^0.8 = 2.23; boundary p = 0.5 where a = 0: x = 3/0.8 = 3.75

The boundary is a hyperplane, so logistic regression cannot learn XOR. Truth table, with an interaction term added in the last column:

x1 x2 XOR x1 + x2 - 2 x1 x2 - 0.5
0 0 0 -0.5
0 1 1 0.5
1 0 1 0.5
1 1 0 -0.5

Proof that no linear rule works: class 1 when w1 x1 + w2 x2 + b > 0 needs b <= 0, w2 + b > 0, w1 + b > 0 and w1 + w2 + b <= 0. Adding the middle two gives w1 + w2 + b > -b >= 0, a contradiction. Enumeration agrees: over all 15,625 linear classifiers with w1, w2, b in {-3, -2.75, ..., 3}, none separates XOR (364 separate AND, 650 separate OR). With the product x1 x2 as an extra feature the last column separates it. That kind of interaction is what the semi-definite logistic regression of Dohi, Wu and Okamura (SOFTENG 2024) adds through a quadratic term x^T B x.

Follow-ups (each builds on your last answer)

  1. Prof: "You said the log-odds is linear in x. What does that assume about how a code metric affects bug risk?"
    You: "It assumes each metric pushes the risk in one direction only, always up or always down as it grows, and that metrics don't interact. Dohi, Wu and Okamura's 2024 bug-prediction paper questions exactly this: for example, more comment lines might lower the risk, not raise it, and lines of code and the number of operators are far from independent. They add a quadratic term, x transpose B x with a symmetric matrix B, to the log-odds, which allows interactions and effects that rise and then fall, or the other way round."
  2. Prof: "How many parameters does that quadratic model have with 37 metrics, and is that a problem?"
    You: "B is symmetric, so it has 37 times 38 over 2, which is 703 free entries, plus 37 linear weights and an intercept, 741 in all. Their cm1 data set has only 327 modules, and they train on 25 to 75 percent of it, so with every metric in, the model has more parameters than training points and would overfit. That's why they drop metrics one at a time for as long as AIC keeps falling."
  3. Prof: "Why does AIC help there? What does it trade off?"
    You: "AIC estimates how well a model would predict new data by charging the fit for its size: it's minus 2 times the maximised log-likelihood plus 2 times the number of free parameters. So each parameter has to raise the log-likelihood by more than 1 to pay for itself. In this model one metric brings its own weight and a whole row of B, 38 parameters when all 37 are in, so dropping it lowers AIC unless it adds more than 38 to the log-likelihood."

ML5. What is the derivative of the sigmoid, and why does it matter?

Say it: "The sigmoid is sigma of a equals 1 over 1 plus e to the minus a, and its derivative is sigma of a times 1 minus sigma of a. It is largest, one quarter, at a equals 0, and goes to zero when a is large in either direction, so a saturated sigmoid passes back almost no gradient."

Worked detail: This is January 2025 II-Q6(2), and the sigmoid is one of the activation functions in August 2024 II-Q6(2)(b).

sigma(a)  = (1 + e^(-a))^(-1)
sigma'(a) = e^(-a) / (1 + e^(-a))^2
          = [1/(1 + e^(-a))] * [e^(-a)/(1 + e^(-a))]
          = sigma(a) * (1 - sigma(a))        because e^(-a)/(1 + e^(-a)) = 1 - 1/(1 + e^(-a))
y(1 - y) on 0 < y < 1 is largest at y = 1/2, so sigma'(a) <= 1/4, reached at a = 0.
Also: sigma(-a) = 1 - sigma(a), and tanh(a) = 2 sigma(2a) - 1  (sympy: both differences simplify to 0)

a      sigma(a)    sigma(a)(1 - sigma(a))    finite difference
0      0.500000    0.250000                  0.250000
0.7    0.668188    0.221713                  0.221713
2      0.880797    0.104994                  0.104994
5      0.993307    0.006648                  0.006648
10     0.999955    0.000045                  0.000045

Follow-ups (each builds on your last answer)

  1. Prof: "You said the derivative is at most a quarter. Why does that matter in a deep network?"
    You: "Backpropagation multiplies one such derivative per layer, so through ten sigmoid layers those factors alone shrink the gradient by at least 4 to the 10, about a million, before the weights even come in. The early layers then barely learn, which is the vanishing gradient problem, and it's why hidden layers now mostly use ReLU, the maximum of 0 and a, whose derivative is 1 for positive inputs."
  2. Prof: "ReLU's derivative is 0 for negative inputs. Isn't that a problem too?"
    You: "It can be: a unit whose input is negative for every example gets zero gradient and never changes again, which is called a dead ReLU. Leaky ReLU fixes this with a small slope, such as 0.01, for negative inputs. A learning rate that's too large makes dead units more likely, because one big step can push a unit's bias far below zero."
  3. Prof: "Our lab has used a ReLU network inside a reliability model. Do you know where?"
    You: "Yes, in the Hawkes-process paper by Qiu, Dohi, Wu, Zheng and Okamura that I cite. Its kernel, which says how much one detected fault raises the rate of later detections, is e to the power of a small ReLU network of the time since that fault, so between the points where units switch on or off it's a plain exponential and the likelihood stays easy to compute. They also say it may overfit mildly late in testing, because the network was chosen by its training likelihood."

ML6. What is the softmax function, and what are its main properties?

Say it: "Softmax turns K real numbers into K probabilities: p_j is e to the z_j over the sum of e to the z_k. Adding the same constant to every z changes nothing, and its derivative is dp_j by dz_i equals p_j times (delta_ij minus p_i). With two classes it is just the sigmoid of z_1 minus z_2."

Worked detail: August 2023 II-Q6 asks for the shift property, the temperature behaviour and the derivative; the full proofs are there. In the lab, Li and Zheng's 2021 malware paper puts a softmax over 8 malware families at the output of its LSTM and GRU networks and trains it with cross-entropy.

shift:      e^(z_j + c) / sum_k e^(z_k + c) = e^c e^(z_j) / (e^c sum_k e^(z_k)) = p_j
derivative: with S = sum_k e^(z_k),
            dp_j/dz_i = [delta_ij e^(z_j) S - e^(z_j) e^(z_i)] / S^2 = p_j (delta_ij - p_i)
            Jacobian = diag(p) - p p^T   (matches finite differences to 3.5e-11 at z = (1, 3, -0.5, 2))
two classes: p_1 = e^(z1)/(e^(z1) + e^(z2)) = 1/(1 + e^(-(z1 - z2))) = sigma(z1 - z2)
temperature: softmax(z/H) -> (1/K, ..., 1/K) as H grows, -> one-hot at the largest z_j as H -> 0

The shift property is also how softmax is computed safely: subtract the largest input first.

#include <stdio.h>
#include <math.h>

/* naive: exp of each input, divided by the sum */
void softmax_naive(const double *z, double *p, int k) {
    double s = 0.0;
    for (int i = 0; i < k; i++) s += exp(z[i]);
    for (int i = 0; i < k; i++) p[i] = exp(z[i]) / s;
}

/* stable: subtract the largest input first (same answer, no overflow) */
void softmax_stable(const double *z, double *p, int k) {
    double m = z[0], s = 0.0;
    for (int i = 1; i < k; i++) if (z[i] > m) m = z[i];
    for (int i = 0; i < k; i++) { p[i] = exp(z[i] - m); s += p[i]; }
    for (int i = 0; i < k; i++) p[i] /= s;
}

int main(void) {
    double small[3] = {0, 1, 2}, big[3] = {1000, 1001, 1002}, p[3];
    softmax_naive(small, p, 3);
    printf("naive  (0,1,2):          %.4f %.4f %.4f\n", p[0], p[1], p[2]);
    softmax_naive(big, p, 3);
    printf("naive  (1000,1001,1002): %.4f %.4f %.4f\n", p[0], p[1], p[2]);
    softmax_stable(big, p, 3);
    printf("stable (1000,1001,1002): %.4f %.4f %.4f\n", p[0], p[1], p[2]);
    return 0;
}

Output:

naive  (0,1,2):          0.0900 0.2447 0.6652
naive  (1000,1001,1002): nan nan nan
stable (1000,1001,1002): 0.0900 0.2447 0.6652

(1000, 1001, 1002) is (0, 1, 2) shifted by 1000, so the right answer is the same 0.0900, 0.2447, 0.6652.

Follow-ups (each builds on your last answer)

  1. Prof: "You subtract the maximum in your code. What exactly goes wrong if you don't?"
    You: "e to the 1000 is far beyond the largest double, about 1.8 times 10 to the 308, so exp returns infinity, and infinity divided by infinity is NaN, not a number. My C run printed nan for all three outputs. Subtracting the maximum makes the largest exponent e to the 0, which is 1, so nothing overflows, and by the shift property the answer is the same."
  2. Prof: "Cross-entropy needs the log of a softmax output. Can that go wrong too?"
    You: "Yes: if a probability rounds to 0, its log is minus infinity. So I compute it directly as log p_j equals z_j minus m minus the log of the sum of e to the (z_k minus m), with m the maximum, which is called the log-sum-exp trick. For z = (0, 800), the naive way gives log of 0, minus infinity, for the first class, while this gives minus 800, right to full double precision."
  3. Prof: "Floating-point problems like this are a classic source of software failures. How would the differential testing in your plan treat a NaN?"
    You: "My plan compares each version's output with the merged code under a float tolerance, so tiny rounding differences don't count, but a NaN or infinity where the merged code returns a number does count as a failure. One detail I'd have to fix in the comparison rule: in Python NaN isn't equal to itself, and math.isclose of two NaNs is also False. So I'd treat two NaNs as the same output, or every version that copies the merged code's NaN would wrongly count as failing."

ML7. Which loss functions do you use, and why cross-entropy for classification?

Say it: "A loss function measures how wrong one prediction is, and training minimises its average over the data. For regression the usual loss is squared error; for classification it is cross-entropy, minus the log of the probability the model gave to the true class. With a sigmoid or softmax output, the gradient of cross-entropy is simply prediction minus target, times the input."

Worked detail: January 2025 II-Q6(1)-(3) is exactly this chain rule.

squared error:         E = (1/2) sum_n (y_n - t_n)^2
binary cross-entropy:  E = - sum_n [ t_n ln y_n + (1 - t_n) ln(1 - y_n) ],  y_n = sigma(a_n), a_n = w^T x_n
K classes:             E = - sum_n sum_k t_nk ln y_nk,  y_n = softmax(a_n)

dE/dy_n  = (y_n - t_n) / (y_n (1 - y_n))
dy_n/da_n = y_n (1 - y_n)
=> dE/da_n = y_n - t_n,   grad_w E = sum_n (y_n - t_n) x_n

Why not squared error with a sigmoid? Take one confidently wrong example, t = 1 and y = 0.01:

cross-entropy:  E = -ln 0.01 = 4.61,  dE/da = y - t = -0.99
squared error:  dE/da = (y - t) y (1 - y) = (-0.99)(0.01)(0.99) = -0.0098

The squared-error gradient is about 100 times smaller exactly when the model is most wrong, so it learns slowly there. Cross-entropy is also convex in w for logistic regression; squared error through a sigmoid is not.

Follow-ups (each builds on your last answer)

  1. Prof: "You said minus the log of the probability of the true class. Where does that come from?"
    You: "It's the negative log-likelihood. If the model says example n is positive with probability y_n, the probability of all the observed labels is the product of y_n to the t_n times 1 minus y_n to the 1 minus t_n, and minus its log is exactly the cross-entropy. So minimising cross-entropy is maximum likelihood, the same principle the lab uses to fit NHPP models."
  2. Prof: "What happens if the model gives probability exactly 0 to the class that turns out to be true?"
    You: "Then the loss is minus log 0, which is infinite, so one confident mistake can dominate the whole sum. In code I compute the loss from the raw outputs with log-sum-exp, or clip the probability away from 0, say at 10 to the minus 15, which caps that loss at about 34.5. It's also a sign that a model shouldn't be allowed to be completely sure."
  3. Prof: "How would you check whether a model's probabilities can be trusted at all?"
    You: "By checking calibration: take all predictions near 0.2 and see whether about 20 percent of those cases really were positive, bin by bin, which is called a reliability diagram. My plan needs the same check, because the vote formulas use the fitted failure probabilities directly. So I'd compare the beta-binomial's predicted number of inputs on which 0, 1, 2 or more runs fail with the observed numbers."

ML8. How does gradient descent work?

Say it: "Gradient descent starts from a guess and repeats w becomes w minus eta times the gradient of the loss, because minus the gradient is the direction in which the loss falls fastest. The learning rate eta sets the step: too small is slow, too large overshoots and can diverge. Stochastic gradient descent uses the gradient on a small random batch at each step, which is cheaper but noisier."

Worked detail: "Name one optimisation method" is January 2025 II-Q6(4); gradient descent, stochastic gradient descent and Newton-Raphson (IRLS) are all listed there as valid answers.

E(w) = (w - 3)^2,  dE/dw = 2(w - 3),  start w_0 = 0
w_(k+1) - 3 = (1 - 2 eta)(w_k - 3)

eta = 0.1: 0, 0.6, 1.08, 1.464, 1.7712, 2.017, ...   distance shrinks by 0.8 a step; 26 steps to get within 0.01
eta = 0.5: 0, 3                                       exact in one step
eta = 0.9: 0, 5.4, 1.08, 4.536, 1.7712, 3.983, ...    overshoots but still converges
eta = 1.0: 0, 6, 0, 6, 0, 6, ...                      bounces for ever
eta = 1.1: 0, 6.6, -1.32, 8.184, -3.2208, 10.465      diverges (factor -1.2)

The same loop fits a logistic regression, with the gradient from ML7:

import numpy as np

x = np.array([1, 2, 3, 4, 5, 6.])
t = np.array([0, 0, 1, 0, 1, 1.])
X = np.column_stack([np.ones_like(x), x])   # column of 1s for the intercept b

def sigmoid(a):
    return 1 / (1 + np.exp(-a))

w = np.zeros(2)                              # start at b = 0, slope = 0
eta = 0.05                                   # learning rate
for step in range(1, 20001):
    y = sigmoid(X @ w)
    grad = X.T @ (y - t)                     # sum of (prediction - target) * input
    w -= eta * grad
    if step in (1, 10, 100, 1000, 20000):
        y = sigmoid(X @ w)
        E = -np.sum(t*np.log(y) + (1-t)*np.log(1-y))   # cross-entropy after the step
        print(f"step {step:5d}: b = {w[0]:7.4f}, slope = {w[1]:6.4f}, E = {E:.4f}")

# Newton-Raphson (IRLS) for comparison
v = np.zeros(2)
for _ in range(25):
    y = sigmoid(X @ v)
    H = X.T @ (X * (y*(1-y))[:, None])
    v -= np.linalg.solve(H, X.T @ (y - t))
print(f"Newton:      b = {v[0]:7.4f}, slope = {v[1]:6.4f}")

Output:

step     1: b =  0.0000, slope = 0.1750, E = 3.8843
step    10: b = -0.3337, slope = 0.2329, E = 3.6269
step   100: b = -2.2276, slope = 0.7010, E = 2.7150
step  1000: b = -4.2143, slope = 1.2051, E = 2.4780
step 20000: b = -4.2491, slope = 1.2140, E = 2.4780
Newton:      b = -4.2491, slope = 1.2140

At the start every y is 0.5, so the gradient for b is sum(0.5 - t) = 0 and b does not move in step 1. The fitted boundary is x = 4.2491/1.2140 = 3.50, halfway through the overlap of the two classes. The data are not perfectly separable, so a finite minimum exists.

Follow-ups (each builds on your last answer)

  1. Prof: "You said too large a step diverges. In your example, where exactly is the limit?"
    You: "Each step multiplies the distance to 3 by 1 minus 2 eta. That shrinks only if the absolute value of 1 minus 2 eta is below 1, so eta must lie between 0 and 1. At eta 0.5 it lands on 3 in one step, at exactly 1 it bounces between 0 and 6 for ever, and at 1.1 the factor is minus 1.2, so every step overshoots further."
  2. Prof: "With many weights, what decides that limit?"
    You: "The curvature, meaning the eigenvalues of the Hessian, the matrix of second derivatives. Near a minimum, gradient descent is stable only if eta is below 2 over the largest eigenvalue, and then it moves slowest along the direction with the smallest eigenvalue. So the ratio of the largest to the smallest, the condition number, decides how many steps it needs."
  3. Prof: "Do you see badly conditioned problems in the reliability models our lab fits?"
    You: "Yes, for example the Goel-Okumoto model, m of t equals a times 1 minus e to the minus b t. Early in testing, when b t is small, that's close to a times b times t, so the data mostly fix the product a b and the likelihood has a long flat ridge, where plain gradient steps crawl. The Hawkes paper I cite fitted its NHPP benchmarks with a particle swarm search followed by L-BFGS-B, a quasi-Newton method, with several restarts."

ML9. What is overfitting, what causes it, and how do you avoid it?

Say it: "Overfitting is when a model learns the noise in its training data along with the real pattern, so it does very well on the training data and badly on new data. The usual causes are a model too flexible for the amount of data, noisy labels, too many features, or training too long. The fixes are more data, a simpler model, regularisation, early stopping, and choosing the complexity by cross-validation."

Worked detail: This is January 2024 II-Q6(1)(a)-(c). An example: 10 evenly spaced points on [0, 1] from sin(2 pi x) plus normal noise with standard deviation 0.2 (numpy seed 1), polynomials of degree 1, 3 and 9 fitted by least squares, then the error on 1,000 fresh points.

Degree Training MSE New-data MSE Largest weight
1 0.2605 0.2553 1.4
3 0.0170 0.0506 30.3
9 0.0000 0.1183 260,023

The noise variance is 0.04, so no model can get much below 0.04 on new data. Degree 1 underfits (high bias: both errors high). Degree 9 has 10 weights for 10 points, passes through every point, and needs huge weights to do it (high variance). Degree 3 is close to the floor.

expected squared error at x = noise variance + bias^2 + variance

In the lab: Li and Zheng's 2021 malware networks use dropout of 0.5 and early stopping against overfitting, and Qiu et al.'s Hawkes paper trains its neural kernel with L2 regularisation and early stopping, and still says it may overfit mildly late in testing.

ML10. What is regularisation, and how do L1 and L2 differ?

Say it: "Regularisation adds a penalty on large weights to the loss, so the model prefers simpler fits. L2, or ridge, adds lambda times the sum of squared weights and shrinks every weight smoothly; L1, or lasso, adds lambda times the sum of absolute weights and sets some weights exactly to zero, so it also selects features. Lambda is chosen by cross-validation."

Worked detail: "Regularisation" is one of the remedies for overfitting in January 2024 II-Q6(1)(c), which asks for at least three.

ridge: minimise ||y - X w||^2 + lambda ||w||^2
       gradient -2 X^T (y - X w) + 2 lambda w = 0  =>  w = (X^T X + lambda I)^(-1) X^T y
       X^T X + lambda I is invertible for every lambda > 0, even when p > n
       (check: n = 5, p = 8 gives rank X^T X = 5, rank X^T X + I = 8)
lasso: minimise (1/2)||y - X w||^2 + lambda sum_j |w_j|   (no closed form in general)

With orthonormal columns (X^T X = I) both have a closed form:
  ridge: w_j = w_ols_j / (1 + lambda)
  lasso: w_j = sign(w_ols_j) * max(|w_ols_j| - lambda, 0)      (soft-thresholding)
Example, w_ols = (3, 0.5, -1.2), lambda = 1:
  ridge (1.5, 0.25, -0.6)      every weight halved
  lasso (2, 0, -0.2)           0.5 is set exactly to 0
(checked on a random 50 x 3 orthonormal design: ridge by the formula, lasso by coordinate descent)

Bayesian reading: ridge is the posterior mode (MAP) under a normal prior on w centred at 0; lasso is the same under a Laplace prior. Elastic net uses both penalties; the lab's APARM 2024 paper uses it for metrics-based reliability models.

Follow-ups (each builds on your last answer)

  1. Prof: "Why does L1 give exact zeros and L2 doesn't?"
    You: "Near zero the L2 penalty is flat, its slope there is 0, so a small weight costs almost nothing and is only shrunk. The L1 penalty keeps a slope of lambda right down to zero, so if the data pull on a weight less strongly than lambda, the best value is exactly zero. In the orthonormal case that's soft-thresholding: an estimate of 0.5 with lambda 1 goes to 0 under lasso, while ridge only halves it to 0.25."
  2. Prof: "You said the weight is shrunk, so the estimate is biased. Why accept that?"
    You: "Because mean squared error is variance plus bias squared, and a small bias can buy a big drop in variance when the data are few or the features are correlated. Ridge also makes X transpose X plus lambda I invertible even when X transpose X isn't, for example with more features than data points. The best lambda is where that trade-off gives the lowest error on held-out data."
  3. Prof: "You said a small bias is worth it when the data are few. Is there a Bayesian way to see that pull toward zero, and does anything like it appear in your plan?"
    You: "Ridge gives the most probable weights, the posterior mode, under a normal prior centred at zero, and lasso does the same with a Laplace prior. In my plan, if every failing run in RQ2 happened to use the same file version, the logistic fit for the version effect would run off to infinity. A weak prior on that effect, or Firth's correction, keeps it finite, which is the same gentle pull toward zero."

ML11. What is K-fold cross-validation, and why use it?

Say it: "K-fold cross-validation splits the data into K parts, trains on K minus 1 of them and measures the error on the part left out, does that K times, and averages the K errors. It estimates how well a model will do on new data, uses every point for checking exactly once, and is how we choose models or settings like lambda. With K equal to n it's called leave-one-out."

Worked detail: This is August 2024 II-Q6(1). With 100 samples and K = 5: five trainings on 80 samples, each checked on the other 20; every sample is checked once and used for training 4 times. After choosing, refit on all the data.

On the 10 points of ML9 (5 folds of 2 points, and leave-one-out):

Degree 5-fold CV MSE Leave-one-out MSE New-data MSE (from ML9)
1 0.5085 0.4467 0.2553
3 0.0576 0.0459 0.0506
9 22.70 162.99 0.1183

Both pick degree 3, which also had the lowest error on new data. Degree 9 looks terrible here because each fold trains 10 weights on only 8 or 9 points.

Three traps: choose features and settings inside each fold, never on all the data first; the best cross-validation error after choosing among many settings is optimistic (use a held-out set or nested cross-validation); and for time-ordered data, train on the past and check on the future.

Follow-ups (each builds on your last answer)

  1. Prof: "Our fault data arrive in time order. Would you shuffle them into folds?"
    You: "No. Shuffling lets the model learn from faults found after the ones it's asked to predict, which leaks the future and makes the estimate too optimistic. I'd fit on the first part and predict the next, then move the cut forward, like the Hawkes paper I cite, which predicts from 20, 50 and 80 percent of the testing period."
  2. Prof: "But the lab's kernel-regression paper does use leave-one-out cross-validation on fault times. Is that wrong, then?"
    You: "No, because there it does a different job. In the 2026 note by Bai, Dohi, Zheng and Okamura, leave-one-out picks the bandwidth, how much to smooth the fault-detection rate, using the training period only, and the forecasts are then judged on the later faults by their mean absolute error. Leaving each fault out stops the fit from choosing a bandwidth so small that every point explains itself."
  3. Prof: "What goes wrong if the bandwidth is too small, or too large?"
    You: "Too small and the estimated rate spikes at every fault time and falls toward zero between them: low bias, high variance, which is overfitting in another form. Too large and it smooths away real changes in the fault rate, which is underfitting. Without leaving each point out, the fit would always prefer a smaller bandwidth, because each point's own spike makes it look well explained."

ML12. What are the confusion matrix, precision, recall and F1?

Say it: "A confusion matrix counts the four outcomes of a yes/no classifier: true positives, false positives, false negatives and true negatives. Precision is TP over everything predicted positive, how many alarms are real; recall is TP over everything really positive, how many real cases we caught. F1 is their harmonic mean, 2PR over P plus R, which works out to 2TP over 2TP plus FP plus FN."

Worked detail: This is August 2025 II-Q6(1)-(2), where the derivation of 2TP/(2TP + FP + FN) is written out. Watch the layout there: it puts TN in the top-left corner. A new example: a bug predictor on 1,000 modules, 100 of them really buggy; it flags 120, and 60 of those are buggy.

                 predicted buggy   predicted clean
really buggy        TP = 60           FN = 40
really clean        FP = 60           TN = 840

accuracy    = (60 + 840)/1000 = 0.90
precision   = 60/120 = 0.50
recall      = 60/100 = 0.60
F1          = 2(0.5)(0.6)/(0.5 + 0.6) = 0.5455 = 2*60/(120 + 60 + 40) = 120/220
specificity = 840/900 = 0.9333, false positive rate = 0.0667
"always clean" also gets accuracy 900/1000 = 0.90
Cohen's kappa: p_e = 0.12*0.10 + 0.88*0.90 = 0.804, kappa = (0.90 - 0.804)/(1 - 0.804) = 0.49

Why the harmonic mean: it is dragged down by the smaller value. With P = 1 and R = 0.01 the arithmetic mean is 0.505 but F1 is 0.0198. The lab's bug-prediction paper (Dohi, Wu and Okamura, SOFTENG 2024) judges its models by exactly these: precision, recall and F-score on NASA's jm1, pc1 and cm1 data.

    You: "No. A model that calls every module clean is also right 900 times out of 1,000, so 0.90 says almost nothing here. With only 10 percent buggy modules, accuracy mostly measures the majority class, so I'd report precision and recall, or Cohen's kappa, which corrects for chance agreement and comes out at about 0.49 here."
  2. Prof: "Have you measured precision and recall on anything of your own?"
    You: "On a small scale, yes. ML13. What are the ROC curve and the AUC?

Say it: "The ROC curve plots the true positive rate, which is recall, against the false positive rate as the decision threshold moves from high to low. The area under it, AUC, is the probability that a randomly chosen positive gets a higher predicted probability than a randomly chosen negative: 0.5 is guessing and 1 is perfect. It doesn't depend on any one threshold, or on the share of positives."

Worked detail: ROC and AUC are not in the six sets, but they are the usual next question after precision and recall (August 2025 II-Q6). Example: 4 positives with predicted probabilities 0.9, 0.8, 0.55, 0.4, and 6 negatives with 0.7, 0.5, 0.35, 0.3, 0.2, 0.1.

sorted: 0.9 P, 0.8 P, 0.7 N, 0.55 P, 0.5 N, 0.4 P, 0.35 N, 0.3 N, 0.2 N, 0.1 N
lower the threshold one item at a time; P moves up by 1/4, N moves right by 1/6
ROC points (FPR, TPR): (0,0) (0,0.25) (0,0.5) (1/6,0.5) (1/6,0.75) (1/3,0.75) (1/3,1) ... (1,1)
area = (1/6)(0.5) + (1/6)(0.75) + (2/3)(1) = 0.0833 + 0.125 + 0.6667 = 0.875
pair count: positive above negative in 6 + 6 + 5 + 4 = 21 of 4*6 = 24 pairs -> 21/24 = 0.875
threshold 0.5 (flag if >= 0.5): TP 3, FP 2 -> TPR 0.75, FPR 0.333, one point on the curve

The pair count is the Mann-Whitney U statistic divided by n_pos n_neg. Rare positives: with 100 buggy modules among 10,000, recall 0.8 at a false positive rate of 0.05 means 80 true alarms and 495 false ones, a precision of 80/575 = 0.139, even though that point sits high on the ROC curve.

  1. Prof: "You said AUC doesn't depend on the share of positives. Is that always an advantage?"
    You: "Not when positives are rare. ML14. What is the Bayes decision rule?

Say it: "For each observation x, the Bayes decision rule takes the action with the smallest expected loss, the conditional risk: R of a_i given x is the sum over j of the loss lambda of a_i given omega_j, times the posterior P of omega_j given x. With 0-1 loss this is just picking the class with the largest posterior probability, and no other rule has a lower expected loss."

Worked detail: This is January 2026 II-Q6 (posteriors 0.8 and 0.2, risks 0.4 and 0.8, and the switch once the loss passes 4); Bayes' theorem itself is 02_probability.md P3. A new example in the lab's own area, software rejuvenation: a memory alarm on a server. omega_1 = healthy, omega_2 = aged (close to an aging failure); the action is restart (rejuvenate) or not.

priors: P(aged) = 0.1, P(healthy) = 0.9
P(alarm | aged) = 0.7, P(alarm | healthy) = 0.1
P(alarm) = 0.7*0.1 + 0.1*0.9 = 0.16
P(aged | alarm) = 0.07/0.16 = 0.4375,  P(healthy | alarm) = 0.09/0.16 = 0.5625

0-1 loss: the larger posterior is "healthy", so do not restart.

losses: restart a healthy server = 1 (planned downtime), leave an aged server running = 5 (a crash), else 0
R(restart | alarm)    = 1*0.5625 + 0*0.4375 = 0.5625
R(no restart | alarm) = 0*0.5625 + 5*0.4375 = 2.1875   -> restart
rule: restart when 5 P(aged|x) > 1 - P(aged|x), i.e. P(aged|x) > 1/6 = 0.167
likelihood-ratio form: restart when P(x|aged)/P(x|healthy) > (1*0.9)/(5*0.1) = 1.8; here 0.7/0.1 = 7
no alarm: P(aged | no alarm) = 0.03/0.84 = 0.0357,
          R(restart) = 0.964 > R(no restart) = 0.179  -> keep running

Follow-ups (each builds on your last answer)

  1. Prof: "You said no other rule has a lower expected loss. Why?"
    You: "The overall expected loss of any rule is the average, over x, of the conditional risk of the action it takes at that x. The Bayes rule takes the smallest possible conditional risk at every single x, so no rule can beat it at any x, and so none can beat it on average. With 0-1 loss, the error that's left over is the Bayes error, the floor for any classifier on that problem."
  2. Prof: "If the Bayes rule is optimal, why do we need machine learning at all?"
    You: "Because it needs the true posterior probabilities, and in practice we don't know them. Machine learning estimates them from labelled data, either directly, as logistic regression does, or through P of x given the class and the priors, as naive Bayes does. The losses are different: they can't be learned from labels, so someone has to set them."
  3. Prof: "Then who sets them? In your restart example, where would real numbers come from?"
    You: "I haven't worked on rejuvenation myself, so I'd start from the 2021 paper by Prof. Zheng, Prof. Okamura and Prof. Dohi on rejuvenation and checkpointing, which picks the policy that maximises steady-state availability, the long-run share of time the system is up. That makes the natural losses expected downtimes: the short planned downtime of a restart against the longer recovery after a crash. I'd measure those from the system's logs, or take them from such a model, before filling in the loss table."

ML15. How does k-means work?

Say it: "k-means splits unlabelled data into k groups. It starts with k centres and repeats two steps until nothing changes: assign each point to its nearest centre, then move each centre to the mean of its points. It minimises the total squared distance from the points to their centres, but only to a local minimum, so we run it from several starts."

Worked detail: k-means is the unsupervised algorithm in the model answer to January 2024 II-Q6(2). The objective is J = sum_i ||x_i - c_(a(i))||^2, where a(i) is the cluster of point i. A trace on numbers on a line:

#include <stdio.h>
#include <math.h>

/* k-means on numbers on a line: assign to nearest centre, move centre to mean */
double kmeans(const double *x, int n, double *c, int k, int verbose) {
    int a[64], changed = 1, it = 0;
    for (int i = 0; i < n; i++) a[i] = -1;
    while (changed) {
        changed = 0;
        for (int i = 0; i < n; i++) {              /* assignment step */
            int best = 0;
            for (int j = 1; j < k; j++)
                if (fabs(x[i] - c[j]) < fabs(x[i] - c[best])) best = j;
            if (best != a[i]) { a[i] = best; changed = 1; }
        }
        for (int j = 0; j < k; j++) {              /* update step */
            double s = 0; int m = 0;
            for (int i = 0; i < n; i++) if (a[i] == j) { s += x[i]; m++; }
            if (m > 0) c[j] = s / m;
        }
        it++;
        if (verbose) {
            printf("iteration %d: centres", it);
            for (int j = 0; j < k; j++) printf(" %.3f", c[j]);
            printf("\n");
        }
    }
    double sse = 0;
    for (int i = 0; i < n; i++) sse += (x[i] - c[a[i]]) * (x[i] - c[a[i]]);
    return sse;
}

int main(void) {
    double x[6] = {1, 2, 4, 7, 8, 10}, c[2] = {1, 2};
    printf("total squared distance %.3f\n\n", kmeans(x, 6, c, 2, 1));

ML16. How does a decision tree work?

Say it: "A decision tree asks a sequence of yes/no questions about the features, like 'is the cyclomatic complexity above 10?', and each leaf gives a prediction. It's grown greedily, choosing at each node the split that most reduces impurity, measured by entropy or the Gini index, and it's pruned or limited in depth so it doesn't overfit. A random forest averages many trees grown on bootstrap samples with random subsets of features."

Worked detail: "Name one machine learning method and explain it" was asked out loud in B2 of 02_questions_others_were_asked.md, and the 100-word written versions are in August 2025 II-Q6(3) and January 2024 II-Q6(2); a tree is an easy one to explain. Example: 20 modules, 8 buggy. The split "complexity > 10" sends 12 modules left (2 buggy) and 8 right (6 buggy).

entropy H(p) = -p log2 p - (1 - p) log2(1 - p)
parent H(8/20) = 0.971
left   H(2/12) = 0.650,   right H(6/8) = 0.811
weighted children = (12/20)(0.650) + (8/20)(0.811) = 0.715
information gain = 0.971 - 0.715 = 0.256 bits

Gini G(p) = 1 - p^2 - (1 - p)^2
parent 0.48, left 0.278, right 0.375, weighted 0.317, decrease 0.163

The tree tries every feature and cut-off and keeps the one with the largest gain (ID3 uses information gain, C4.5 the gain ratio, which divides the gain by the entropy of the split itself, and CART uses Gini). Random forest averaging: if each tree's prediction has variance sigma^2 and any two trees have correlation rho, the average of B trees has

Var = rho sigma^2 + (1 - rho) sigma^2 / B
sigma^2 = 1, rho = 0.3:  B = 1 -> 1.000,  B = 10 -> 0.370,  B = 100 -> 0.307,  B = 1000 -> 0.3007
simulation with B = 50: 0.3128 against the formula's 0.314

Follow-ups (each builds on your last answer)

  1. Prof: "You said trees are pruned so they don't overfit. What happens if you never stop growing one?"
    You: "It keeps splitting until every leaf is pure, so if no two modules have identical features it can fit the training data perfectly, down to one leaf per module. That's zero training error and high variance: a small change in the data gives a very different tree. A minimum leaf size, a maximum depth, or pruning chosen by cross-validation keeps that in check."
  2. Prof: "You said high variance. How does a random forest bring it down?"
    You: "By averaging many trees, each grown on a bootstrap sample and choosing each split from a random subset of features. If each tree has variance sigma squared and two trees have correlation rho, the average of B trees has variance rho sigma squared plus 1 minus rho over B times sigma squared. More trees remove the second term, and the random feature subsets lower rho, which sets the floor."
  3. Prof: "That floor, rho sigma squared, looks familiar. How does it relate to your plan?"
    You: "It's the same idea: averaging or voting helps only as far as the members aren't correlated, and adding more members can't get below the shared part. In my plan rho is the correlation between agent runs' failures, so if runs that read one AGENTS.md fail together, voting over more of them helps less than independence predicts. Prof. Zheng also has a 2026 paper on random-forest defect prediction tuned with metaheuristics, which I know only by its title so far."
