Chapter 36 of 62

Information theory and coding

When and how long: 30 minutes.

Part II Question 1 is information or coding theory in all six program sets from August 2023 to January 2026, so a professor could ask you a quick question on it out loud, even though it is far from your plan. This file covers Aug 2023 II-Q1 (a prefix code, its tree, the second extension, unique decodability), Jan 2024 II-Q1 (an erasure channel: conditional entropy, mutual information, capacity), Aug 2024 II-Q1 (entropy, a code that is not instantaneous, Huffman on the second extension, H(U²) = 2H(U)), Jan 2025 II-Q1 (decoding a (7,4) Hamming code), Aug 2025 II-Q1 (Hamming distance, generator matrix, syndrome), Jan 2026 II-Q1 (a memoryless source, its entropy and its second extension) and the older set II-Q1 (entropy, a Huffman code, H(S) ≤ L̄).

Part 1 is the short list of ideas to say out loud. Part 2 has 16 questions (IT1 to IT16), each with a spoken answer, the full working and three follow-ups.

How the answers were checked. Every number in this file was computed in Python 3.14 on 13 Nov 2026 (scripts in /tmp/fu_it/). The three C programs were compiled with Apple clang 21 and run, and their real output is pasted under each one. The parity truth table, the Hamming (7,4) syndromes, the unique-decodability checks (Sardinas-Patterson) and the claims about two-dimensional parity were checked by enumerating every case. Shannon's English figures were checked against his 1951 paper and the DEFLATE fact against RFC 1951. The Yuki secret-filter fact in IT1 was checked against the "Secret filter" section of yuki-2.0/docs/MEMORY.md.

Part 1. Short notes

1.1 Information and entropy

  • Information of one outcome. I(x) = -log p(x) bits. Say: "A rare outcome is more surprising, so it carries more information: a one-in-a-thousand event carries about 10 bits."
  • Entropy. H(X) = -Σ p(x) log p(x). Say: "Entropy is the average information per outcome, roughly how many fair yes-or-no questions I need on average to learn the outcome."
  • Bounds. 0 ≤ H(X) ≤ log n for n outcomes. It is 0 only when one outcome is certain, and log n only when all n are equally likely.
  • Binary entropy. h(p) for a yes-or-no event with probability p. h(0.5) = 1 bit, h(0.1) = 0.469 bits. Say: "A fair coin carries 1 bit; a coin that lands heads 90 percent of the time carries less than half a bit, because it is predictable."
  • Joint entropy. H(X, Y) = -Σ p(x, y) log p(x, y): the entropy of the pair taken as one variable.
  • Conditional entropy. H(Y | X) = Σ_x p(x) H(Y | X = x). Say: "The uncertainty left in Y once I know X, averaged over X."
  • Chain rule. H(X, Y) = H(X) + H(Y | X) = H(Y) + H(X | Y).
  • Conditioning reduces entropy on average. H(Y | X) ≤ H(Y), with equality only if X and Y are independent. One particular H(Y | X = x) can still be larger than H(Y) (IT3).
  • Mutual information. I(X; Y) = H(Y) - H(Y | X) = H(X) - H(X | Y) = H(X) + H(Y) - H(X, Y). Say: "How much knowing one variable tells me about the other. It is symmetric, never negative, and zero exactly when they are independent." It is at most min(H(X), H(Y)).
  • Relative entropy (Kullback-Leibler divergence). D(p || q) = Σ p(x) log(p(x)/q(x)) ≥ 0, zero only when p = q, and not symmetric. Mutual information is D(p(x, y) || p(x) p(y)), the distance of the joint distribution from independence. Akaike built AIC as an estimate of this kind of distance between the true distribution and a fitted model.

1.2 Sources

  • Memoryless source. Each symbol is drawn independently with the same fixed probabilities. Say: "The past tells you nothing about the next symbol."
  • Markov source. The next symbol's probabilities depend on the current state (usually the last symbol) through a transition matrix P. Its stationary distribution π solves π = πP.
  • Entropy rate of a Markov source. H = Σ_i π_i H(row i of P). Say: "Memory makes a source more predictable, so its entropy per symbol is below that of a memoryless source with the same symbol frequencies."
  • Extensions. The n-th extension Sⁿ treats each block of n symbols as one symbol, so q symbols give qⁿ blocks. For a memoryless source, P(block) is a product and H(Sⁿ) = n H(S). For a stationary Markov source, H(S²) = 2H(S) - I(S₁; S₂), which is smaller.

1.3 Source coding

  • Classes of codes. Nonsingular (distinct codewords) contains uniquely decodable (every bit string splits one way) contains instantaneous, also called prefix-free (no codeword is the start of another). Say: "Prefix-free means I can output each symbol the moment its last bit arrives."
  • Kraft inequality. A binary prefix code with lengths l₁, ..., l_q exists exactly when Σ 2^(-lᵢ) ≤ 1. McMillan showed that every uniquely decodable code satisfies the same inequality, so nothing is lost by insisting on a prefix code.
  • Source coding theorem. For any uniquely decodable code, L̄ ≥ H. The best prefix code has H ≤ L̄ < H + 1. Coding blocks of n symbols gives H ≤ L̄ₙ/n < H + 1/n, so the cost per symbol can get as close to H as we like.
  • Huffman's algorithm. Repeatedly merge the two least likely items until one is left; each merge adds one bit to every symbol inside it. It gives the shortest average length among codes that code one symbol at a time. L̄ = H exactly when every probability is a power of 1/2.
  • Efficiency. H / L̄. Redundancy is 1 minus the efficiency.

1.4 Channels

  • Channel. A table of P(y | x): what comes out given what went in.
  • Capacity. C = max over input distributions p(x) of I(X; Y), in bits per channel use. Say: "Capacity is the most information per use that can get through reliably."
  • Binary symmetric channel (BSC) with flip probability p: C = 1 - h(p), reached with equally likely inputs. For p = 0.1, C = 0.531.
  • Binary erasure channel (BEC) with erasure probability ε: C = 1 - ε. An erasure is less harmful than a flip because the receiver knows which symbols it lost.
  • Channel coding theorem (Shannon). Every rate below C can be sent with error probability as small as we like, using long enough blocks; no rate above C can.

1.5 Error detection and correction

  • Parity bit. The XOR of the data bits, so the whole word has an even number of 1s. It detects any odd number of flipped bits, misses any even number, and cannot say which bit is wrong.
  • Hamming distance. d(x, y) = the number of positions where x and y differ. The minimum distance d of a code is the smallest distance between two different codewords.
  • What d buys. A code with minimum distance d detects up to d - 1 errors, or corrects up to ⌊(d - 1)/2⌋. To correct t and also detect s ≥ t at the same time, it needs d ≥ t + s + 1.
  • Linear codes. Codewords are x = mG (generator matrix G). The check matrix H has H xᵀ = 0 for every codeword. The syndrome of a received word, s = H yᵀ, equals H eᵀ, so it depends only on the error pattern e.
  • Hamming (7,4). 4 data bits, 3 check bits, d = 3, corrects any single error. The columns of H are all seven nonzero 3-bit vectors, so a nonzero syndrome names the wrong bit. Adding one overall parity bit gives the extended (8,4) code with d = 4: single error correction, double error detection (SECDED), as in ECC memory.
  • Detection or correction. Detection plus resending (ARQ) needs less redundancy. Correction without resending (forward error correction) is used when resending is slow or impossible: memory, storage, space links.
  • CRC. The bits are read as a polynomial and the remainder after dividing by a fixed generator of degree r is sent. It catches every burst of length r or less when the generator has a constant term. Ethernet uses a 32-bit CRC.

1.6 Where this meets the lab's work

  • A 2-out-of-3 vote over program versions is a repetition code of length 3 (d = 3): it outvotes one wrong version. The coding numbers assume independent errors, which is exactly what Eckhardt and Lee showed fails for versions that share hard inputs: the vote fails with probability E[3θ² - 2θ³], not 3p² - 2p³.
  • Comparing two versions only detects (like d = 2). Two versions with the same wrong output are like an error pattern that is itself a codeword: invisible.
  • pysrat reports an AIC for each fitted NHPP model, and AIC is an estimate of relative entropy. So "which model fits best" is an information theory question.

Part 2. Questions with spoken answers

IT1. What is entropy? Compute it for a fair coin and for a coin that lands heads with probability 0.9.

Say it: "Entropy is the average information, or surprise, per outcome: H is minus the sum of p log base 2 of p, in bits. A fair coin has 1 bit. The 0.9 coin has about 0.47 bits, because it is more predictable."

Worked detail:

H(fair) = -(0.5 log 0.5 + 0.5 log 0.5) = 0.5 + 0.5 = 1 bit
H(0.9)  = -(0.9 log 0.9 + 0.1 log 0.1) = 0.1368 + 0.3322 = 0.469 bits

Entropy is largest for the fair coin and falls to 0 as p goes to 0 or 1. The rare outcome (tails, 0.1) carries -log 0.1 = 3.32 bits of information, but it happens only a tenth of the time.

Follow-ups (each builds on your last answer)

  1. Prof: "Why a logarithm, and why base 2?"
    You: "Because information from independent events should add up. Their probabilities multiply, and a logarithm turns a product into a sum, so minus log p is the natural measure, up to the choice of base. Base 2 gives bits: the answer to one fair yes-or-no question is exactly 1 bit."
  2. Prof: "Then how many bits per character does a random hexadecimal string carry, and how does English text compare?"
    You: "A uniformly random hex digit is one of 16 equally likely symbols, so it carries log base 2 of 16, which is 4 bits, the maximum for 16 symbols. English is far from uniform: Shannon's 1951 paper gives about 4.14 bits per letter from letter frequencies alone, against 4.70 for 26 equally likely letters. Using long context, he estimated roughly 1 bit per letter."
  3. Prof: "So could you spot secrets such as API keys in text by their high entropy?"
    You: "I tried that in the secret filter of Yuki 2.0, my desktop agent: flag strings of 20 or more mixed characters above 3.5 bits per character. It wrongly flagged 16 of my 167 harmless look-alike strings, including every git hash and SSH public key, and caught almost nothing the known key formats missed, so I dropped it. A git hash is random hex at about 3.7 bits per character, so entropy alone cannot tell a secret from a hash."

IT2. A memoryless source has four symbols with probabilities 1/2, 1/4, 1/8 and 1/8. What is its entropy, and what is the largest entropy any four-symbol source can have?

Modelled on Aug 2024 II-Q1(1) (1/2, 1/4, 1/4 gives 1.5 bits), Jan 2026 II-Q1(2) (1/2, 1/3, 1/6 gives 1.459 bits) and older set II-Q1(1) (2.45 bits).

Say it: "H is a half times 1, plus a quarter times 2, plus two eighths times 3, which is 1.75 bits. The maximum for four symbols is log base 2 of 4, which is 2 bits, and only the uniform distribution reaches it."

Worked detail:

H = (1/2) log 2 + (1/4) log 4 + (1/8) log 8 + (1/8) log 8
  = 0.5 + 0.5 + 0.375 + 0.375 = 1.75 bits
maximum = log 4 = 2 bits;  redundancy = 1 - 1.75/2 = 0.125

Every probability is a power of 1/2, so the prefix code 0, 10, 110, 111 (lengths 1, 2, 3, 3 = -log p) has average length exactly 1.75. A fixed-length code needs 2 bits. When the question gives log 3 ≈ 1.6, as in Jan 2026, use it: (1/3) log 3 ≈ 0.533.

Follow-ups (each builds on your last answer)

  1. Prof: "Why is the uniform distribution the maximum?"
    You: "Because log base 2 of n minus H of p equals the relative entropy between p and the uniform distribution, the sum of p times log of p over one n-th, and relative entropy is never negative. It is zero only when p is uniform. Here it is 2 minus 1.75, so 0.25 bits."
  2. Prof: "Show me why relative entropy is never negative."
    You: "I use the fact that ln t is at most t minus 1. Minus D of p and q is the sum of p log of q over p, which is at most 1 over ln 2 times the sum of p times (q over p minus 1). That is 1 over ln 2 times (the sum of q minus the sum of p), which is 1 minus 1, so zero, and equality needs q over p equal to 1 everywhere, that is q = p."
  3. Prof: "Where does relative entropy show up in our lab's work?"
    You: "In model selection. Akaike built AIC in 1973 as an estimate of the expected relative entropy between the true distribution and a fitted model, and pysrat's README shows each fitted NHPP model reporting its AIC. Wu, Dohi and Okamura's 2024 chapter asks whether the model that information criteria pick also predicts bugs best, and the abstract says that is not guaranteed; I have only read the abstract."

IT3. What are joint entropy and conditional entropy? Work them out for two program versions A and B that each fail on 10 percent of inputs and both fail on 4 percent.

Modelled on the H(Y | X) part of Jan 2024 II-Q1(2).

Say it: "Joint entropy H(X, Y) is the entropy of the pair taken together. Conditional entropy H(Y | X) is the uncertainty left in Y once I know X, averaged over X, and the chain rule says H(X, Y) = H(X) + H(Y | X). Here H(X, Y) is about 0.884 bits and H(X) is 0.469, so H(Y | X) is about 0.415 bits."

Worked detail: X = 1 if A fails, Y = 1 if B fails, on a random input.

B fails (Y = 1) B passes (Y = 0) total
A fails (X = 1) 0.04 0.06 0.10
A passes (X = 0) 0.06 0.84 0.90
total 0.10 0.90 1 
H(X) = H(Y) = h(0.1) = 0.469
H(X,Y) = 0.04 log(1/0.04) + 2 (0.06 log(1/0.06)) + 0.84 log(1/0.84)
       = 0.1858 + 0.4871 + 0.2113 = 0.884
H(Y|X) = H(X,Y) - H(X) = 0.884 - 0.469 = 0.415

Check from the definition:
P(B fails | A fails) = 0.04/0.1 = 0.4      P(B fails | A passes) = 0.06/0.9 = 0.0667
H(Y|X) = 0.1 h(0.4) + 0.9 h(0.0667) = 0.1 (0.971) + 0.9 (0.353) = 0.097 + 0.318 = 0.415

Follow-ups (each builds on your last answer)

  1. Prof: "You said conditioning leaves less uncertainty. Can it ever leave more?"
    You: "On average, no: H of Y given X is at most H of Y, with equality only under independence. But for one value of X it can: knowing that A failed raises B's failure chance to 0.4, so H of Y given X = 1 is h of 0.4, about 0.971 bits, more than H of Y, 0.469. The case where A passes has probability 0.9 and lowers the uncertainty enough to bring the average down to 0.415."
  2. Prof: "What does that 0.4 mean if B is a backup for A?"
    You: "That the backup fails 40 percent of the time exactly when it is needed, against 10 percent on average. A 1-out-of-2 system fails only when both fail, so its failure probability is 0.04, four times the 0.01 that independence would predict."
  3. Prof: "How would you estimate that 0.4 from data, and how sure would you be?"
    You: "I'd run both versions on, say, 10,000 random inputs; about 1,000 make A fail, and among those I count how many also make B fail, about 400. The standard error is the square root of 0.4 times 0.6 over 1,000, about 0.015. So the 95 percent interval is about 0.37 to 0.43."

IT4. What is mutual information? Compute it for the same two versions.

Modelled on Jan 2024 II-Q1(3), which asks for I(X; Y) = H(Y) - H(Y | X).

Say it: "Mutual information is how much knowing X reduces my uncertainty about Y: I(X; Y) = H(Y) minus H(Y | X). It is symmetric, never negative, and zero exactly when X and Y are independent. Here it is 0.469 minus 0.415, about 0.054 bits."

Worked detail:

I(X;Y) = H(Y) - H(Y|X)          = 0.469 - 0.415         = 0.054 bits
       = H(X) + H(Y) - H(X,Y)   = 0.469 + 0.469 - 0.884 = 0.054 bits
upper limit: min(H(X), H(Y)) = 0.469 bits

Independence would give P(both fail) = 0.1 × 0.1 = 0.01, not 0.04, so I > 0 as expected. Mutual information has no sign: with P(both fail) = 0, P(only A) = P(only B) = 0.1, P(neither) = 0.8 (the versions never fail together), I(X; Y) = 0.016 bits, also positive.

Follow-ups (each builds on your last answer)

  1. Prof: "0.054 bits sounds tiny. Is the dependence small?"
    You: "Not in the way that matters: the joint failure probability is 0.04, four times the 0.01 that independence gives. Mutual information averages over all four cases, and both passing, at 0.84, dominates, so rare failures give small numbers. Its ceiling here is only H of X, 0.469 bits, so I'd report the ratio of 4 next to it."
  2. Prof: "Compute the correlation between the two failure indicators. How does it relate to the rho in your plan?"
    You: "The covariance is 0.04 minus 0.01, which is 0.03, and each variance is 0.1 times 0.9, which is 0.09, so the correlation is one third. If A and B were two runs from one setting, rho is exactly this correlation, the variance of theta over p times 1 minus p. So here the variance of theta would be 0.03, and P of both failing is p squared plus that, 0.01 plus 0.03."
  3. Prof: "So why not use mutual information as your dependence measure instead?"
    You: "For two yes-or-no variables it adds little: zero correlation already means independence there, so both see the same thing. Mutual information also has no sign, so versions that fail on different inputs, which is good for voting, and versions that fail on the same inputs, which is bad, both give a positive number. And the vote's failure probability needs P of both failing directly, which rho gives."

IT5. What is a memoryless source, and what is a Markov source?

Modelled on Jan 2026 II-Q1(1) ("Explain what a memoryless information source means").

Say it: "A memoryless source draws each symbol independently with the same fixed probabilities, so the past tells you nothing about the next symbol. In a Markov source the next symbol's probabilities depend on the current state, usually the last symbol, through a transition matrix. Memory makes a source more predictable, so its entropy per symbol is lower than that of a memoryless source with the same symbol frequencies."

Worked detail: a binary Markov source. From 0 it stays at 0 with probability 0.9 and moves to 1 with 0.1; from 1 it goes either way with 0.5.

P = | 0.9  0.1 |      stationary: pi0 (0.1) = pi1 (0.5), pi0 + pi1 = 1
    | 0.5  0.5 |      so pi1 = 0.1/0.6 = 1/6, pi0 = 5/6
eigenvalues of P: 1 and 0.4

entropy rate = pi0 h(0.1) + pi1 h(0.5) = (5/6)(0.469) + (1/6)(1) = 0.391 + 0.167 = 0.557 bits/symbol
memoryless source with the same frequencies (1/6 ones): h(1/6) = 0.650 bits/symbol

Block entropies per symbol, H(block of n)/n: 0.650 (n = 1), 0.604 (n = 2), 0.576 (n = 5), 0.567 (n = 10), falling toward 0.557.

Follow-ups (each builds on your last answer)

  1. Prof: "How did you get the stationary probabilities five sixths and one sixth?"
    You: "In the long run the flow from 0 to 1 must equal the flow back, so pi0 times 0.1 equals pi1 times 0.5. With pi0 plus pi1 equal to 1, that gives pi1 = 0.1 over 0.6, one sixth, and pi0 = five sixths. Equivalently, pi is the left eigenvector of the transition matrix for eigenvalue 1."
  2. Prof: "Does the source have to start in that distribution?"
    You: "No. The chain can reach both states and is not periodic, so it forgets its start: the other eigenvalue is 1 minus 0.1 minus 0.5, which is 0.4, so the distance to the stationary distribution shrinks by a factor of 0.4 each step. Starting from 0, the chance of being in state 1 goes 0.1, 0.14, 0.156 and on toward 0.167, and the entropy rate is a long-run average, so the start does not matter."
  3. Prof: "So in the long run about one symbol in six is a 1. Where would a source like this appear in reliability work?"
    You: "As a pass and fail sequence where a failure makes the next failure more likely: here a fail is followed by another fail half the time, against 0.1 after a pass. That is the idea of the self-exciting Hawkes models in Qiu et al., where each detected fault raises the chance of more soon after, though theirs work in continuous time. Many of the lab's availability models, like Prof. Zheng's work on virtualized systems, are continuous-time Markov chains over working and failed states too."

IT6. What is the second extension of a source, and why is H(S²) = 2H(S) for a memoryless source?

Modelled on Aug 2024 II-Q1(4) (prove H(U²) = 2H(U)), Jan 2026 II-Q1(3)-(4) (pair probabilities and H(U²)) and Aug 2023 II-Q1(3) (write out the extension of a code).

Say it: "The second extension treats each pair of symbols as one new symbol, so q symbols give q squared pairs. If the source is memoryless, a pair's probability is the product of the two probabilities, the log of a product is a sum, and the entropy splits into H(S) plus H(S)."

Worked detail: proof. Let S have probabilities p₁, ..., p_q. Memoryless means P(sᵢ sⱼ) = pᵢ pⱼ.

H(S^2) = - sum_i sum_j pi pj log(pi pj)
       = - sum_i sum_j pi pj (log pi + log pj)
       = -(sum_i pi log pi)(sum_j pj) - (sum_i pi)(sum_j pj log pj)
       = H(S) (1) + (1) H(S) = 2 H(S)

Example: S with probabilities 3/4 and 1/4. H(S) = h(1/4) = 0.811. The pairs have probabilities 9/16, 3/16, 3/16, 1/16 and H(S²) = 0.467 + 0.453 + 0.453 + 0.250 = 1.623 = 2 × 0.811.

Follow-ups (each builds on your last answer)

  1. Prof: "You said 'if the source is memoryless'. What happens for a Markov source?"
    You: "Then a pair's probability is P of the first symbol times P of the second given the first, and H of the pair is H of S1 plus H of S2 given S1, which is 2H of S minus the mutual information between neighbours. For the Markov source with switching probabilities 0.1 and 0.5, that is 0.650 plus 0.557, about 1.208 bits, instead of 1.300, a gap of 0.093 bits."
  2. Prof: "So pairs carry less than twice as much. Why would anyone code pairs for a memoryless source?"
    You: "Because a binary code spends at least 1 bit on every symbol. For probabilities 3/4 and 1/4 the entropy is 0.811 bits, but any one-symbol-at-a-time code costs 1 bit. Huffman on the pairs, with probabilities 9/16, 3/16, 3/16 and 1/16, gives lengths 1, 2, 3 and 3 and 27/16 bits per pair, about 0.844 bits per symbol."
  3. Prof: "Then why not blocks of ten symbols? What does it cost?"
    You: "The gain shrinks while the cost grows: the bound is H plus 1 over n, and with blocks of 8 Huffman is already at about 0.816 against 0.811. But the table has 2 to the n codewords, 1,024 for blocks of ten, all their probabilities must be known, and the encoder waits for n symbols before it sends anything. Arithmetic coding gets the same gain without building a table, which is why many modern compressors use it or range coding."

IT7. What is the difference between a uniquely decodable code and an instantaneous code? Is the code {0, 01, 11} instantaneous?

Modelled on Aug 2024 II-Q1(2) (this exact code) and Aug 2023 II-Q1(1), (4).

Say it: "Uniquely decodable means every bit string splits into codewords in only one way. Instantaneous means I can output each symbol as soon as its last bit arrives, which happens exactly when no codeword is a prefix of another. {0, 01, 11} is uniquely decodable but not instantaneous, because 0 is a prefix of 01."

Worked detail:

code for s₁, s₂, s₃ nonsingular uniquely decodable instantaneous
0, 1, 01 yes no: 01 is s₁s₂ or s₃ no
0, 01, 11 yes yes no: 0 is a prefix of 01
0, 10, 11 yes yes yes

IT8. State the Kraft inequality. Can a binary prefix code have codeword lengths 1, 2, 3, 3? And 1, 1, 2?

Modelled on Aug 2023 II-Q1(1)-(2) (choose a codeword so the code is prefix-free, draw its tree) and step 1 of older set II-Q1(3).

Say it: "A binary prefix code with lengths l1 to lq exists exactly when the sum of 2 to the minus li is at most 1, and McMillan showed every uniquely decodable code obeys the same bound. Lengths 1, 2, 3, 3 give a half plus a quarter plus two eighths, exactly 1, so yes. Lengths 1, 1, 2 give 1.25, so no such code exists."

Worked detail:

lengths 1,2,3,3 : 1/2 + 1/4 + 1/8 + 1/8 = 1      -> possible, e.g. 0, 10, 110, 111
lengths 1,1,2   : 1/2 + 1/2 + 1/4      = 5/4    -> impossible (0 and 1 use up the whole tree)
Aug 2023 code {0, 110, 10, 1110}: 1/2 + 1/8 + 1/4 + 1/16 = 15/16 < 1 (the leaf 1111 is unused)

Proof of the inequality (tree argument): let L be the longest length. A codeword of length l sits at depth l of a binary tree and has 2^(L - l) descendants at depth L. No codeword is a prefix of another, so these sets of descendants do not overlap, and there are only 2^L nodes at depth L. So Σ 2^(L - lᵢ) ≤ 2^L; divide by 2^L.

Construction from lengths (canonical code): sort the lengths; the first codeword is all zeros; each next codeword is the previous one plus 1, with zeros appended to reach the new length. For 1, 2, 3, 3: 0, then 1 → 10, then 11 → 110, then 111. (Python check: this gives prefix-free codes for 1, 2, 3, 3 and 2, 2, 2, 3, 3.)

Follow-ups (each builds on your last answer)

  1. Prof: "You said the sum is at most 1. Why?"
    You: "Put the codewords on a binary tree and extend every branch down to depth L, the longest length. A codeword of length l owns 2 to the L minus l of the 2 to the L bottom nodes, and because no codeword is a prefix of another, these sets do not overlap. So the sum of 2 to the L minus l is at most 2 to the L, and dividing by 2 to the L gives the inequality."
  2. Prof: "And the other direction: build me a prefix code with lengths 1, 2, 3, 3."
    You: "The first codeword is 0. Next I add 1 to get 1 and append a 0 for length 2, giving 10; then 10 plus 1 is 11, and appending 0 gives 110; then 110 plus 1 is 111. So the code is 0, 10, 110, 111, and this always works when the Kraft sum is at most 1."
  3. Prof: "Is that construction used in anything real?"
    You: "Yes, it is the canonical Huffman code in DEFLATE, the format inside zip, gzip and PNG. The file stores only the code length of each symbol, and RFC 1951 fixes the order so the decoder rebuilds the exact codes from the lengths, which saves sending the code table itself."

IT10. What does the source coding theorem say, and why can no code beat the entropy?

Modelled on older set II-Q1(3) ("Show that H(S) ≤ L̄(S)").

Say it: "For any uniquely decodable binary code, the average length is at least the entropy, and the best prefix code gets below H plus 1. Coding blocks of n symbols brings the cost per symbol below H plus 1 over n, so we can get as close to H as we like. The lower bound comes from the Kraft inequality together with the fact that relative entropy is never negative."

Worked detail:

Lower bound. With qi = 2^(-li) and sum qi <= 1 (Kraft), using ln t <= t - 1:
  H - L = sum pi log(2^(-li) / pi) <= (1/ln 2) sum pi (2^(-li)/pi - 1)
        = (1/ln 2) (sum 2^(-li) - 1) <= 0,  so H <= L,
  with equality exactly when pi = 2^(-li) for every i.

Upper bound. Take li = ceil(-log pi) (Shannon's lengths).
  Then 2^(-li) <= pi, so sum 2^(-li) <= 1 and a prefix code exists (Kraft),
  and li < -log pi + 1, so L < H + 1. Huffman is optimal, so it does at least as well.

Example: p = 0.99 and 0.01, H = h(0.01) = 0.0808 bits. Shannon's lengths are ⌈0.0145⌉ = 1 and ⌈6.64⌉ = 7, so L̄ = 0.99 + 0.07 = 1.06. Huffman uses 0 and 1, so L̄ = 1. Huffman on blocks of n symbols (Python), bits per symbol:

n 1 2 5 10
Huffman L̄ₙ/n 1.000 0.515 0.226 0.136
bound H + 1/n 1.081 0.581 0.281 0.181

Follow-ups (each builds on your last answer)

  1. Prof: "Where does the plus 1 in the upper bound come from?"
    You: "From Shannon's choice of lengths: l equals minus log base 2 of p, rounded up. Rounding up makes 2 to the minus l at most p, so the Kraft sum is at most 1 and a prefix code exists. Rounding up also adds less than 1 bit to each length, so the average is below H plus 1, and Huffman, being optimal, can only do better."
  2. Prof: "So is Shannon's code as good as Huffman's? Try probabilities 0.99 and 0.01."
    You: "Not always. Shannon's lengths are 1 and 7, because minus log base 2 of 0.01 is 6.64, rounded up to 7, so the average is 0.99 plus 0.07, which is 1.06 bits; Huffman just uses 0 and 1, 1 bit. Both are within H plus 1, but the entropy is only about 0.081 bits, so both waste over 90 percent."
  3. Prof: "Say those are pass and fail results from a million runs. How would you store them near the entropy?"
    You: "The entropy says about a million times 0.081, roughly 81,000 bits, about 10 kilobytes against 125 for one bit per run. IT11. What is channel capacity? Work it out for a binary symmetric channel that flips each bit with probability 0.1.

Modelled on Jan 2024 II-Q1(4) (the capacity of a channel with flips and erasures; with no erasures it reduces to this one).

Say it: "Capacity is the largest mutual information between input and output, maximised over the input distribution: the most bits per use that can get through reliably. For a binary symmetric channel it is 1 minus h(p), reached with equally likely inputs. For p = 0.1 that is 1 minus 0.469, about 0.531 bits per use."

H(Y) <= 1, with equality when P(Y=1) = 1/2.
P(Y=1) = r(1-p) + (1-r)p = p + r(1 - 2p), which is 1/2 exactly when r = 1/2.
C = 1 - h(p);   C(0.1) = 1 - 0.469 = 0.531 bits per use

C code: 7 data bits plus a parity bit, then one and two flipped bits. A check of 0 means "looks fine".

#include <stdio.h>

/* even parity bit: XOR of all bits, so the word plus the bit has an even number of 1s */
int parity(unsigned x) {
    int p = 0;
    while (x) {
        p ^= x & 1u;
        x >>= 1;
    }
    return p;
}

int main(void) {
    unsigned data[] = {0x59, 0x00, 0x7F, 0x2A};  /* 1011001, 0000000, 1111111, 0101010 */
    for (int i = 0; i < 4; i++) {
        unsigned d = data[i];
        unsigned sent = (d << 1) | (unsigned)parity(d);       /* 7 data bits + parity bit = 8 bits */
        unsigned one = sent ^ 0x10;                            /* flip one bit */
        unsigned two = sent ^ 0x18;                            /* flip two bits */
        printf("data 0x%02X  parity %d  check(sent) %d  check(1 flip) %d  check(2 flips) %d\n",
               d, parity(d), parity(sent), parity(one), parity(two));
    }
    return 0;
}

IT14. What is Hamming distance, and how many errors can a code with minimum distance d detect and correct?

#include <stdio.h>

/* Hamming distance: count the 1s in a XOR b (x &= x - 1 clears the lowest 1) */
int hamming_distance(unsigned a, unsigned b) {
    unsigned x = a ^ b;
    int count = 0;
    while (x) {
        x &= x - 1;
        count++;
    }
    return count;
}

int main(void) {
    printf("d(00000, 11111) = %d\n", hamming_distance(0x00, 0x1F));
    printf("d(10110, 10011) = %d\n", hamming_distance(0x16, 0x13));
    printf("d(1011101, 1001001) = %d\n", hamming_distance(0x5D, 0x49));
    return 0;
}

IT15. How does the (7,4) Hamming code correct a single error? Encode 1011, flip one bit, and decode.

Modelled on Jan 2025 II-Q1 (decode with a given check matrix) and Aug 2025 II-Q1(2)-(3) (generator matrix, syndrome of the error vector).

Say it: "Four data bits get three parity bits, each checking a different group of positions. At the receiver I recompute the three checks; the pattern of failed checks, the syndrome, is the column of H at the wrong bit, so I flip that bit. Here 1011 encodes to 0110011, an error at position 5 gives syndrome 101, which is 5 in binary, and flipping bit 5 restores the codeword."

Worked detail: positions 1 to 7; parity bits at 1, 2 and 4; data bits d₁ d₂ d₃ d₄ at 3, 5, 6, 7.

p2 checks positions 2,3,6,7:  p2 = d1 ^ d3 ^ d4
p4 checks positions 4,5,6,7:  p4 = d2 ^ d3 ^ d4

message 1011: d1=1 d2=0 d3=1 d4=1  ->  p1 = 1^0^1 = 0, p2 = 1^1^1 = 1, p4 = 0^1^1 = 0

The H in Jan 2025 has the same seven columns in a different order, so it is the same kind of code with the bits renamed.

C code: encode, flip, correct, then check all cases.

#include <stdio.h>

/* bit i of the word (i = 1..7) is stored in bit (i - 1) of an unsigned */
static int get(unsigned w, int i) { return (w >> (i - 1)) & 1u; }

/* message bits d1 d2 d3 d4 go to positions 3, 5, 6, 7; parity bits sit at 1, 2, 4 */
unsigned encode(int d1, int d2, int d3, int d4) {
    int p1 = d1 ^ d2 ^ d4;   /* covers positions 1, 3, 5, 7 */
    int p2 = d1 ^ d3 ^ d4;   /* covers positions 2, 3, 6, 7 */
    int p4 = d2 ^ d3 ^ d4;   /* covers positions 4, 5, 6, 7 */
    int b[8] = {0, p1, p2, d1, p4, d2, d3, d4};
    unsigned w = 0;
    for (int i = 1; i <= 7; i++) w |= (unsigned)b[i] << (i - 1);
    return w;
}

/* syndrome = XOR of the positions that hold a 1; 0 means "codeword" */
int syndrome(unsigned w) {
    int s = 0;
    for (int i = 1; i <= 7; i++)
        if (get(w, i)) s ^= i;
    return s;
}

unsigned correct(unsigned w) {
    int s = syndrome(w);
    return s ? (w ^ (1u << (s - 1))) : w;
}

void show(const char *label, unsigned w) {
    printf("%s ", label);
    for (int i = 1; i <= 7; i++) printf("%d", get(w, i));
    printf("  syndrome %d\n", syndrome(w));
}

int main(void) {
    unsigned c = encode(1, 0, 1, 1);
    show("sent     ", c);
    unsigned r = c ^ (1u << 4);          /* flip position 5 */
    show("received ", r);
    show("corrected", correct(r));

    int ok1 = 0, wrong2 = 0, n2 = 0;
    for (int m = 0; m < 16; m++) {
        unsigned x = encode(m & 1, (m >> 1) & 1, (m >> 2) & 1, (m >> 3) & 1);
        for (int i = 0; i < 7; i++)
            if (correct(x ^ (1u << i)) == x) ok1++;
        for (int i = 0; i < 7; i++)
            for (int j = i + 1; j < 7; j++) {
                n2++;
                if (correct(x ^ (1u << i) ^ (1u << j)) != x) wrong2++;
            }
    }
    printf("single errors corrected: %d of 112\n", ok1);
    printf("double errors miscorrected: %d of %d\n", wrong2, n2);
    return 0;
}

Follow-ups (each builds on your last answer)

  1. Prof: "Why do the parity bits sit at positions 1, 2 and 4?"
    You: "Because 1, 2 and 4 are the positions whose binary number has a single 1, so each parity bit is in exactly one check and can be set on its own. Check i covers every position whose binary number has that bit set, so the failed checks spell out the wrong position in binary, and every data position, like 3, which is 011, sits in at least two checks."
  2. Prof: "So every nonzero syndrome points to a position. What does that tell you about the code?"
    You: "That no syndrome is wasted: 7 nonzero syndromes for 7 positions. Counting words, each of the 16 codewords has itself plus 7 neighbours at distance 1, and 16 times 8 is 128, every 7-bit word, so the radius-1 balls fill the space exactly. That is what a perfect code means: it meets the Hamming bound with equality."
  3. Prof: "Perfect sounds ideal. Would you use it on a channel that flips 10 percent of bits?"
    You: "No. A block fails with 2 or more errors, which at p = 0.1 is 1 minus 0.9 to the 7, minus 7 times 0.1 times 0.9 to the 6, about 15 percent. Its rate, 4 sevenths or 0.571, is above that channel's capacity of 0.531, so no code at that rate can be made reliable there; perfect only means no wasted words, not enough redundancy. At p = 0.01 the same code loses about 0.2 percent of blocks, against 3.9 percent for 4 unprotected bits."

IT16. What is the difference between error detection and error correction, and when would you choose each?

Pulls together Jan 2025 II-Q1(3) (why 2 errors cannot be corrected) and Aug 2025 II-Q1(1)(b) (how many errors a code corrects).

Say it: "Detection only tells me the word is wrong, so I ask for it again; correction works out the right word without asking. With minimum distance d, a code detects d minus 1 errors but corrects only about half that, so detection needs less redundancy. I'd detect when resending is cheap, like network packets, and correct when it isn't, like memory chips or a space probe."

Worked detail:

detection plus resend (ARQ) correction (forward error correction)
needs d ≥ s + 1 to catch s errors d ≥ 2t + 1 to fix t errors
cost a return channel and extra delay when errors happen more check bits on every block
typical use Ethernet CRC, TCP checksum ECC memory (SECDED), storage, QR codes, space links
fails silently when the error pattern is itself a codeword more than t errors: the decoder picks a wrong codeword

Example: 7 data bits plus parity, p = 0.01. A word is resent when an odd number of bits flip (0.0746), so on average 1/(1 - 0.0746) = 1.08 sends per word, and a wrong word is accepted with probability 0.0028 per delivered word.

The same idea with program versions: two versions compared with each other can only detect (like d = 2); three versions with a 2-out-of-3 vote can outvote one wrong version (like d = 3).

Follow-ups (each builds on your last answer)

  1. Prof: "You said two versions can only detect. What should a system do when they disagree?"
    You: "The same as a receiver that detects an error: trust neither answer and fall back. That could be re-running, switching to a safe default, or asking a third version or a person, which is roughly what recovery blocks with an acceptance test do in software fault tolerance. The cost is that some inputs get a late answer or none, so detection trades availability for safety."
  2. Prof: "When does comparing two versions miss a failure completely?"
    You: "When both give the same wrong output, the comparison just sees agreement. That is like an error pattern that happens to be a codeword: the syndrome is zero, so nothing is detected. My plan has the same blind spot, since a bug that the merged reference code shares cannot be seen by comparing against it."
  3. Prof: "How would you estimate how often two versions agree on a wrong output?"
    You: "My plan counts runs that fail on the same input, and it counts the 2-out-of-3 vote as failed whenever two runs fail, which is the cautious choice. To split that, I'd keep each failing run's output and count inputs where two failing runs return the same value, because only those fool a voter; different wrong outputs give no majority and can be flagged. I haven't done that yet, and it would use the same notion of equal outputs that I use against the merged code."
