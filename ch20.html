9. Yuki 2.0 (and the older Yuki for Mac)

W39. What is Yuki 2.0?

A voice assistant for Windows that operates the computer for you. You say what you want, and it clicks, types and runs commands until the task is done, talking back as it works. It reads the real buttons and fields from the Windows accessibility tree instead of screenshots. I wrote it in plain Python with the Anthropic SDK, with no agent framework.

If they push ("Who uses it?"): "Only me so far. It runs on my own PC, and there's no public release yet. The code is public on GitHub."

W40. Why the accessibility tree and not screenshots?

The tree gives the real buttons and fields by name, so a click lands on the exact element instead of a guessed pixel, and each step is faster and cheaper. It also needs no screenshots, so the screen stays private.

If they push ("What doesn't it see?"): "Apps that don't expose their controls well. Yuki 2.0 measures how readable a window is instead of guessing."

W41. How do you test it?

I replay real requests on a copy of the memory database with simulated apps. For example, the separate safety checker held 9 of 9 actions the user hadn't asked for, and wrongly held 0 of 36 that the user had asked for. The weakness is sample size: often one run per task.

W42. Is 9 out of 9 good evidence?

It's small. With 9 out of 9, a 95% exact interval for the catch rate still goes down to about 66%. And 0 false holds out of 36 still allows a false-hold rate up to about 10%. So it's a good sign, not a proof.

On paper: the lower bound for 9 of 9 is 0.025^(1/9), about 0.66. The upper bound for 0 of 36 is 1 - 0.025^(1/36), about 0.10. The rule of three gives 3/36, about 0.08, as a quick one-sided bound. Why they ask: this is the cleanest place to show you can put an interval on your own number.

W43. How does the safety checker work, and why does it see only the user's words?

Before any step that can't be undone, like sending or deleting, a separate small model sees only the user's own words and the proposed step. It never sees screen text or tool results, and it says no when in doubt. So a web page can't talk it into anything.

W44. Yuki keeps a confidence score for what it learned: (S + 1) / (S + F + 2), times a time decay. What is that formula?

It's Laplace's rule of succession. With S successes and F failures and a uniform Beta(1, 1) prior on the success chance, the posterior is Beta(S + 1, F + 1), and its mean is (S + 1)/(S + F + 2). Yuki multiplies it by 0.5 to the power of days over a half-life, so old evidence counts less.

If they push ("Connect it to your plan."): "It's the same Beta and binomial family. In my plan the Beta describes how the failure chance varies across inputs, and the count of failing runs is beta-binomial." Note for you: the formula is in yuki/memory/practice.py (fact sheet, section 2b). Say "computed in code, not asked of a model".

W45. Most commits in your Yuki 2.0 repository say "Co-Authored-By: Claude". How much did you write yourself?

I used coding agents such as Claude Code as tools for parts of the work. I made the design decisions, and I reviewed and tested the changes. The design rules are mine: no screenshots, permission by whether an action can be undone, and a checker that sees only the user's words.

If they push ("So could you rebuild it without the agents?"): [CONFIRM: your honest answer.] Something like: "More slowly, yes. I know how every part works, and I'm happy to explain any of it now." Note for you: this is answer-sheet item C8. Make sure it matches how you describe your own work.

W46. Is Yuki your own code? I see a Mac version built on another project.

Yuki for Mac is built on a fork of MacOS-Use, an MIT-licensed agent for macOS, and about half of its Python code is that vendored core. It's credited in the README. Yuki 2.0 is a separate rewrite for Windows that I started from scratch on 22 September 2026, without the fork.

14. BCS301 and your statistics

What BCS301 covered and why it is your only statistics course: 03_weak_points_and_honest_answers.md item 1. Hypothesis tests, ANOVA and the mixed model: 10_other_likely_questions.md Q18. The questions below are the next ones.

W62. Which parts of BCS301 do you use in your plan?

The binomial distribution, because the beta-binomial builds on it. Hypothesis tests, because the Knight and Leveson z that I use as a baseline is a large-sample test. Joint distributions, covariance and correlation, because RQ1 is about the correlation between runs. And ANOVA, which leads to the mixed model with task as a random effect.

W63. What does the central limit theorem say, and where does it show up in your plan?

The average of many independent values from the same distribution is close to normally distributed, whatever that distribution is, as long as its variance is finite. It's why the Knight and Leveson z can be compared with a normal distribution, and why a normal interval for a failure probability works when there are enough failures.

If they push ("When does it break?"): "With very few failures. With 0 failing inputs the normal interval is useless, so I'd use an exact interval or the rule of three."

W64. What is the difference between a 95% confidence interval and "a 95% chance the true value is in this range"?

The interval is built so that, over many repeats of the study, 95% of such intervals contain the true value. For one computed interval, the true value is either in it or not. The "95% chance" reading is the Bayesian credible interval.
