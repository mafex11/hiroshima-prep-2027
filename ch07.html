0. If you only read one section

Item Answer
Lab Dependable Systems Laboratory (REL), Graduate School of Advanced Science and Engineering, Hiroshima University. Faculty of Engineering, Building A1, 7th floor, Higashi-Hiroshima. Site rebuilt 1 Aug 2026: https://www.rel.hiroshima-u.ac.jp/en/
Faculty Prof. Tadashi Dohi, Prof. Hiroyuki Okamura, Assoc. Prof. Junjun Zheng, Specially Appointed Asst. Prof. Jingchi Wu
Students 3 doctoral, 10 master's, 7 undergraduate, 2 research students (member page; names not published)

Best day-to-day match Prof. Junjun Zheng (first author of the N-version paper). Prof. Okamura for testing and tools. Prof. Dohi as the formal supervisor.
Lab motto to quote "In every case we pair the technique with conventional probabilistic evaluation, because what matters is showing quantitatively how much the quality actually improved." (dev-support page)
What the proposal does with it (v2) RQ1: treats repeated agent runs as N versions and fits a beta-binomial model of coincident failure (Eckhardt and Lee [11]) to get shared-failure correlation, 2-out-of-3 vote failure and the cost-optimal number of runs. RQ2: failure probability beyond the PR's tests (10,000+ inputs per entry point), with BCD boundary inputs [2] as a separate stress test. Field study only if time permits, with an NHPP that lets each merged change add faults. Rule compliance is only a manipulation check.

1. The lab

1.1 Themes, in the lab's own words

From https://www.rel.hiroshima-u.ac.jp/en/research/ (fetched 26 Oct 2026). "Dependable denotes a generalized notion of high reliability that unifies fault tolerance and fault avoidance." Six areas:

  1. Software reliability modelling: "When should testing stop, and when is a release safe? Probabilistic models that estimate reliability from failure data." The page says the work "centres on software reliability growth models based on non-homogeneous Poisson processes (NHPP), and extends to self-exciting models using Hawkes processes, interval estimation by parametric bootstrap, and long-range failure prediction".
  2. Supporting software development: test generation (boundary value analysis as an optimisation problem, extended "using machine learning to estimate the boundary itself"; GANs and diffusion models for test inputs), model-driven development in Julia (JuliaMBD.jl), effort prediction. The key sentence for him: "More recently we have turned to large language models, asking whether generative AI can strengthen N-version programming and how cooperation among multiple agents should be designed."
  3. Numerical analysis of stochastic models: phase-type distributions, Markovian arrival processes, EM algorithm.
  4. Optimal maintenance and replacement.
  5. Dependability and performance evaluation: software rejuvenation ("Our laboratory was among the first to ask when rejuvenation should be performed"), checkpointing, cloud and 5G performance, stochastic Petri nets.
  6. Security: malware classification (RNN, GNN, transformers) and NHPP models of vulnerability discovery and patch timing.

"For prospective students" page: "Our tools are probability, statistics, and optimisation." "Recent work applies machine learning and large language models to automated test generation." Students learn "Reasoning with probability and statistics", programming "in Julia, Python, R, or Rust", and research writing. "Prospective graduate students from outside the university are also welcome to get in touch." Most master's graduates go to software development, QA or data analysis.

Official themes in the program's supervisor list (from NOTES.md): Reliability and Maintenance, Dependable computing, Fault tolerant computing, Computer security, Performance evaluation, Operations research, Software reliability engineering, Formal engineering methods for software development, Software testing and formal verification, Intelligent software engineering environment.

1.2 Tools the lab releases (all on GitHub; https://www.rel.hiroshima-u.ac.jp/en/tools/)

  • Software reliability: pysrat (Python, NHPP models), Rsrat (R), Rphsrm (phase-type SRMs), msrat (SRMs with development metrics), gof4srm (goodness of fit: Kolmogorov-Smirnov, EIC), shinyRsrat (web front end). Older and unsupported: phsrm (Java), SRATS2017 and SRATS2010 (Excel add-ins).
  • Development support: JuliaMBD.jl.
  • Stochastic models: PhaseTypeInference.jl, NMarkov.jl, DEQuadrature.jl, mapfit (CRAN), deformula (CRAN).
  • Dependability: gospn (stochastic Petri nets, Go), relibmss (BDD/MDD reliability, Python), relib-rs (Rust).

pysrat in detail (README read in full, https://github.com/SwReliab/pysrat; PyPI 0.2.7, uploaded 21 Sep 2026; MIT licence, copyright Hiroyuki Okamura; the only GitHub contributor is okamumu, whose profile says Hiroyuki Okamura, Hiroshima University):

  • scikit-learn style API: model.fit(data), params_, llf_, aic_. EM updates in C++ through pybind11.
  • 12 models: Exponential, Gamma, Pareto2, Truncated Normal, LogNormal, Truncated Logistic, LogLogistic, Truncated and Log Extreme Value (max and min), and CF1 (canonical phase-type).
  • Data: grouped intervals, counts per interval, or time data (NHPPData.from_intervals).
  • Metrics-based models (MFLogitNHPP, MFProbitNHPP, MFCloglogNHPP) where software metrics are covariates of the fault-detection probability, with AIC stepwise selection; an offset turns the cloglog model into a Cox proportional hazards model.
  • PR-NHPP regression (fit_pr_nhpp): "module-wise NHPP models with a Poisson regression outer loop. Each module has its own fault data ... while the static metrics of the modules explain the differences between their expected fault counts." Warning in the README: with q metrics and m modules the model is not identified when 1 + q >= m; the bundled Tomcat example uses 3 metrics on 6 modules. The outer loop converges slowly (812 iterations in the example; default cap 10,000).
  • (my note) Version 1 of the proposal used PR-NHPP for the field study. Version 2 drops it, because a finite-fault NHPP assumes one fixed code base and agent code keeps arriving; it uses pysrat's distribution families only as the delay G in m(t) = sum_j omega_j G(t - tau_j). If the lab prefers PR-NHPP, the identifiability limit (1 + q < m) still applies.

1.3 People

  • Prof. Tadashi Dohi (土肥 正). Professor. Dean of the School of Informatics and Data Science until 31 Mar 2026; Prof. Masaaki Nagahara is dean from 1 Apr 2026 (source in NOTES.md). OpenAlex lists 46 works from 2024 on. Recent first-author students: Jingchi Wu (bootstrap, least squares, likelihood-free estimation for NHPP SRMs), Nanxiang Qiu (Hawkes and NHMP SRMs), Jiacheng Bai (kernel regression for long-term prediction), Jing Wu (age replacement), Xiujing Guo (test generation). Co-chaired the AISQ workshop at ISSRE 2025 (Crossref: "Message from the AISQ Co-Chairs ISSREW 2025", T. Dohi and Zheng Zheng, DOI 10.1109/issrew67781.2025.00018). AISQ ("International Workshop on Advanced Intelligent Software Applications", 3rd edition in 2026) covers the quality of CPS, ML-based, multi-agent and LLM-based systems; its 2026 call even names "prompt engineering and harness engineering" as new topics (https://sites.google.com/view/aisq-2026/home). Co-author of "Improved V-Method and Its Tool Support for Specification-Based Testing" (Shaoying Liu et al., IEEE TSE 2026; not read).
  • Prof. Hiroyuki Okamura (岡村 寛之). Professor. Author of pysrat and the lab's other packages. Supervised Xiujing Guo's doctorate (chief examiner, 主査, on her 2024 dissertation review; Dohi and Shaoying Liu were examiners). Co-editor of the SFPVV 2025 proceedings (LNCS 16356, with Yuting Chen and Shaoying Liu; Crossref book record 10.1007/978-981-95-6032-5), the volume that holds the N-version paper. Works on test generation, SRM estimation, phase-type and Markov models, fault trees in Julia.
  • Assoc. Prof. Junjun Zheng. First author of the N-version paper [1]. Also: availability of non-Markovian models with rejuvenation and checkpointing, sensitivity of Markov regenerative processes, server cluster performance, 5G handover with stochastic Petri nets, and co-author of an LLM multi-agent paper (Yu et al., "Toward Scalable LLM-Based Multi-Agent Collaboration: A Dynamic Task Graph Approach with Asynchronous Parallel Execution", Electronics 15(11), 2026; with Jingchi Wu; not read, MDPI blocked my downloads). Note: OpenAlex merges his record with a different Junjun Zheng at Alibaba (RecGPT, ShopX etc.). Those are not his.
  • Dr. Jingchi Wu. Specially Appointed Assistant Professor. Statistics for NHPP SRMs: fine-grained parametric bootstrap (JSS 2026), thinning-based bootstrap (DASC 2025), probabilistic least squares (WSSE 2025), likelihood-free estimation (IOCMA 2026), bagging and boosting predictors (PRDC 2024). His HU dissertation was on wavelet methods for software reliability.

1.4 What the lab does NOT do (as far as I found)

No paper on coding agents, AGENTS.md or CLAUDE.md, pull request mining or agent harnesses. Closest LLM work is [1] (code generation by LLMs for N-version programming) and the multi-agent paper. So the repository-mining and agent side of the proposal is mine to bring; the lab supplies the reliability measurement.

Notes for the call

  • Prof. Dohi passed your proposal to Prof. Zheng and said he will retire in a few years. Do not ask him about it.
  • Prof. Okamura is in copy on the emails and may join the call. He made pysrat and works on testing and reliability tools.
  • Address them as Prof. Zheng, Prof. Okamura, Prof. Dohi (or Zheng-sensei, Okamura-sensei, Dohi-sensei).
