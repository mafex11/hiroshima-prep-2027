Part 1: Before Monday's meeting (30 Oct to 2 Nov)

Chapter 10 of 28

Weak points and honest answers

When and how long: Sunday, 30 minutes.

These are the places where Prof. Zheng (or the oral exam panel) could push. For each one: the weak point, then one or two honest sentences to say. Short and true beats long and clever.

About you

1. Your statistics background is thin. "My only statistics course so far is BCS301 in my third semester: distributions, Markov chains, hypothesis tests and ANOVA. That's why probability, statistics and reliability courses come first in my plan."

2. You have no research publications. "I was second of four authors on a 2023 review paper in a college special issue of IJIRAE. It was a review, not my own experiment. I haven't published research of my own yet."

3. You have only read the abstract of his N-version paper. "I've only read the abstract, because the full text is behind the Springer paywall. Could I ask you for a copy?"

4. You haven't used Julia or R, and haven't run pysrat. "Not yet. I use Python every day, and I'm happy to learn whatever the lab uses." (Change this if you install pysrat and run its example before Monday.)

5. Your Japanese is beginner level. "I'm a beginner, below N5. I want to reach N5 before I arrive and keep studying in Japan. Could I work in English in the lab at first?"

6. You work full time. "I'll leave Layerpath before I enrol and study full time."

7. You are also applying to NAIST. "Yes, I'm also applying to NAIST for October 2027. Their official application is in February. If I'm admitted here, I'll tell you my decision quickly and honestly."

8. Funding. "I'm self-funded. I've planned for the enrolment fee and two years of tuition, about 1.35 million yen, plus living costs."

About the research

9. You have never run the experiment. "Right. The pilot in the first half of Year 1 will check the cost, the number of runs, and whether the checkers and input generators work."

10. 10 runs per setting might be too few to estimate ρ. "The pilot will show whether 10 runs give a useful interval for ρ. If not, I'd change the number then."

11. Many inputs may never fail, so the data is mostly zeros. "Then a zero-inflated beta-binomial may fit better. The pilot will show which one fits."

12. "Same failure" is hard to define for code. "I compare each version with the merged code under a fixed rule: a float tolerance, the same exception class, and order ignored for unordered collections. I check 20 disagreements per task by hand."

13. The merged code may itself be wrong. "That's the honest limit. If the merged code has the same bug, this kind of testing can't see it. I drop inputs where I find the merged code is wrong."

14. Results may not generalise beyond these tasks, agents and models. "Yes. It's 10 tasks in Python, two commercial agents and one open-weight model at fixed versions. I'll report it as that, and release everything so others can repeat it."

15. Claude Code and Codex don't let you set the temperature. "As far as I know, neither CLI documents a temperature setting. So I treat each setting as a distribution of runs, and I vary temperature only in my own harness."

16. Removing a rule might change nothing. "A checker confirms each manipulation changed what the agent did. If replacing a rule changes nothing in reliability, that's a result too."

17. Cost: 420 to 590 US dollars. "That's at the per-task costs in Gloaguen et al., and newer models may cost more. I'd ask whether it fits a lab budget, and if not, move more runs to the open-weight model." Never imply the lab must pay.

18. Boundary value testing can't estimate failure probability. "Right, so I use your lab's boundary method only as an extra stress test, not for the estimates."

19. Public pull requests may be in the models' training data. "Where possible I add pull requests merged after the models' training cutoff, and I report older tasks separately."

20. Flaky tests. "I only keep tasks whose tests fail before the change and pass after it, and I would re-run the tests to drop flaky ones."

Things never to say

  • "Most of my code is written by agents."
  • "No one has ever done this." Say "as far as I know".
  • "I have read your paper" (only the abstract so far).
  • Anything about Burnt.
  • That BrandMemory was a study. It was one A/B comparison.
